# [test] marker AST-attach — symmetric with [impl] (the scoreboard-integrity fix)

**Author:** robbin-architect · 2026-08-07. PO TOP priority (outranks the 1003-corruption repair) — a Test that credits a FILE with no per-assertion scope is a claim that cannot fail, sitting UNDER the scoreboard. Design → expert extends the marker audit → tester's blast-radius number and this gate must AGREE. Folds into R-C3's fail-closed family.

## MEASURED (disk, HEAD)
- **The asymmetry is real:** `[impl:uuid]` markers are AST-gated (`strict-marker-audit.ts`: PASS iff the marker HEADS a named member declaration, name-matched, via the TS AST). `[test:uuid]` markers have **NO equivalent rule** — `trace-audit` does not validate them at all. That absence IS the hole.
- **Blast radius (I ran it):** **387 `[test:uuid]` markers total → 335 FILE-STACKED (invalid, no per-assertion scope) + 52 assertion-ATTACHED.** ~87% credit a file, not an assertion. Worst: server.test.ts 68/70, components.test.ts 64/76, room.test.ts 50/56, scenario.test.ts 49/50, file-dnd-chain.test.ts 11/14. (Consequence the tester found: 3 A1 rows cite Tests whose files have grep=0 for the claimed behaviour — chain reads complete-to-Test, asserts nothing.)

## The symmetric rule (mirror [impl])
1. **AST-ATTACH (INV-T1):** a `[test:uuid]` marker confers chain-credit ONLY if it **HEADS a specific test/assertion block** — an `it()` / `test()` / `describe()`-leaf CallExpression — AST-attached (the marker comment immediately precedes that block), with the block's title **name/intent-matched to the Test unit** (exactly as `[impl]` name-matches its declaration). Reuse `strict-marker-audit.ts`'s TS-AST engine; add a `[test:uuid]` pass that finds the marker's nearest FOLLOWING `it/test/describe` node and verifies it heads it + title matches.
2. **FAIL-CLOSED (INV-T2):** ONLY a **PROVEN-COMPLETE** marker (AST-attached, name-matched) confers chain-credit. An **UNPROVEN** (not-attached, backable-in-principle) or **PROVEN-FICTIONAL** (un-backable/mis-scoped) marker confers **NO** chain-credit — `trace-audit` reports it in its bucket, never silently counts it complete-to-Test. A Test whose only marker is not proven-complete reads honestly incomplete. ([[false-low-worse-than-absent]].) The difference between UNPROVEN and FICTIONAL is the BACKLOG LABEL + path (re-attach vs write-test), not the credit — neither counts until proven.
3. **CLASSIFY + AGREE (INV-T3):** the audit buckets every marker with counts, and gate == tester == planner. ★ ONE shared predicate `isTestMarkerAttached(node, unit)` (TS-AST "marker heads a name-matched it/test/describe node") — my quick 335/52 used a 2-line-proximity heuristic; the AST is authoritative. Single-source ([[one-parser-one-source]]).
   **★ FILE-SET — pinned (planner caught my narrow glob dropping 284 markers; corrected):** the shared set is **all `.ts/.js/.mjs` under `test/` (recursive, ANY name — INCLUDES `test/visual/*-gate.mjs` dedicated-gate files) + `src/**/*.{test,spec}.{ts,js,mjs}`, EXCLUDING `dist/ node_modules/ .git/`.** My earlier `/\.(test|spec)\./` glob was WRONG — it dropped the `*-gate.mjs`/`visual/` files (284 markers, e.g. d82ebcf5 in r255-v0694-gate.mjs), so my written predicate did NOT reproduce my own baseline. Measured BROAD set = **672 markers / 253 files** (matches tester 652/301 + planner 674/255 ballpark). **★ OUT-OF-SCOPE STRAY (flag, never drop):** a `[test:uuid]` in any file NOT in this set (measured: 1 — `scripts/generate-sprint-md.ts:1` = 9dbf5538, a marker on a generator with no `it()` blocks) is REPORTED as `test-marker-outside-scope` = INVALID, 0 credit — never silently counted, never silently dropped (closes the blind-spot both directions). The file-set is part of the ONE shared module; gate + tester + planner ALL import it, so the 387-vs-652 denominator gap CANNOT recur.
   **★ WHY BROAD is correctness, not cosmetics (PO):** the excluded `*-gate.mjs` are our BEST tests — per-assertion, stub-falsifiable gates (r255-v0694-gate.mjs, rc1refine-frozen-cancelled-metabite.ts). Under the narrow glob they'd be INVISIBLE → any Test pointing at them classifies UNPROVEN or worse → we'd strip credit from the evidence we trust MOST = the mirror error of inflating (erasing real work). BROAD protects them.
   **★ ALL FOUR DIMENSIONS in ONE exported definition (we've now diverged on every one):** the shared module exports a single `analyzeTestMarkers()` whose contract OWNS all four — (1) **glob** (BROAD, above), (2) **marker regex** `/\[test:uuid:([0-9a-f-]{8,36})\]/gi`, (3) **it()-block detection** (AST `it/test/describe` CallExpression — authoritative over the line-regex proxy), (4) **counting-basis** (markers = occurrences; the pigeonhole compares marker-occurrences vs it()-blocks per file). No party re-implements ANY of the four — gate, tester baseline, and planner ranking all call `analyzeTestMarkers()`. Four dimensions, one source.

## Migration policy — THREE honest buckets (PO reconcile 2026-08-07, supersedes "335 lose credit NOW")
Two measurements were BOTH right measuring DIFFERENT things: mine = **335/387 not-AST-attached**; tester's = **73/652 PROVABLY UN-BACKABLE** (a file with MORE `test:uuid` markers than `it()/test()` blocks — pigeonhole PROOF some can't back anything: server.test.ts 70/30 = 40 over, room 54/30 = 24 over). The tester CORRECTED its own first metric (52%→73) on finding HEALTHY suites legitimately keep uuids in top comments WITH ample assertions (components.test.ts 163 `it()` / 74 markers). ★ **KEY: 'not AST-attached' ≠ 'fictional'** — many stacked markers have REAL assertions merely unattached. My binary was too coarse; **erasing real work is as dishonest as inflating it** (both-directions rule). So credit is graded by PROVABILITY into three VISIBLY-DISTINCT buckets:
- **(1) PROVEN-COMPLETE** — AST-attached to a name-matched `it()/test()` block, on-scope. → **credit STANDS** (my 52 + tester-verified).
- **(2) UNPROVEN** — marker not attached, but the file plausibly HAS the assertion (blocks ≥ markers; assertion may exist). → **credit SUSPENDED, not denied**; labelled `unproven — needs re-attach`; mechanical path back (move the marker onto its real block). Not fiction, just unproven.
- **(3) PROVEN-FICTIONAL** — un-backable (the 73: markers > blocks, pigeonhole) OR read-and-confirmed mis-scoped (the 3 A1 rows). → **credit DENIED** + it means a REAL TEST MUST BE WRITTEN — tracked as untested-feature debt, NEVER hidden in the re-attach pile.

**Classifier (INV-T4, the ONE shared predicate emits ALL THREE buckets):** `classifyTestMarker(marker, testUnit) → PROVEN_COMPLETE | UNPROVEN | PROVEN_FICTIONAL`. Rules: AST-attached + name-match → COMPLETE; not-attached but file has `it()`-blocks ≥ markers (backable in principle) → UNPROVEN; file markers > `it()`-blocks (pigeonhole un-backable) OR confirmed mis-scoped → FICTIONAL. **FAIL-CLOSED toward the lower-credit bucket** on ambiguity (never promote to COMPLETE without a proven attach; never bury a FICTIONAL in UNPROVEN). The audit emits `{ complete, unproven, fictional }` counts.

**★ INV-T3 (single-source) is the reconciler:** the 87%-vs-11.2% divergence — AND the 387-vs-652 total divergence (my scan was narrower) — is EXACTLY the drift the shared predicate exists to kill. Both my gate and the tester's baseline **import the SAME `classifyTestMarker` over the SAME file-set + SAME marker regex**, so there is ONE number per bucket, not two heuristics. That is the single-source lesson applied to a MEASUREMENT (the PO's "do that everywhere").

**Justification:** false credit is worse than a lower score (session thesis, applied to our own scoreboard) — BUT suspending is not denying; bucket (2) preserves real-but-unproven work rather than erasing it. The score moves HONESTLY in both directions. Don't delete markers (the Test↔file pointer survives). `--strict` drains: (2) via re-attach, (3) via writing real tests — different work, tracked separately; only (3) is genuine untested debt.

## Forward guard
New/edited `[test]` markers MUST AST-attach — extend `strict-marker-audit.ts` to `[test:uuid]` and add it to `ci:gates`. A file-stacked marker FAILS the build → the hole cannot grow. This is the symmetric partner to the existing `[impl]` gate.

## GATE — BITE
- **attach BITE:** a `[test:uuid]` heading a name-matched `it()` → VALID/credits; the SAME uuid stacked at file-top → INVALID/no-credit (proves file-stacking confers nothing).
- **name-match BITE:** a marker heading an `it()` whose title does NOT match the Test unit's intent → INVALID (credit requires intent-match, not just any block).
- **count-agreement BITE:** the audit's stacked-count == the tester's measured count (shared AST predicate).
- **A1 BITE:** the 3 A1 rows citing grep=0 Tests → those Tests read NOT-complete-to-Test after the rule (the false-green is gone).
- **3-bucket classify BITE:** AST-attached name-matched → **PROVEN-COMPLETE** (credits); not-attached but file `it()`-blocks ≥ markers → **UNPROVEN** (suspended); file markers > `it()`-blocks (pigeonhole, server.test.ts 70/30) OR read-confirmed mis-scoped (3 A1 rows) → **PROVEN-FICTIONAL** (denied + write-test); ambiguous → fail-closed to the lower bucket. All three counts emitted distinctly; `fictional` never folded into `unproven`.
- **single-source BITE:** gate and tester baseline import the SAME `classifyTestMarker` over the SAME file-set → identical per-bucket counts (the 87-vs-11 + 387-vs-652 divergence goes to ZERO).
- **forward BITE:** a new file-stacked marker → `ci:gates` RED.
- **idempotent** + `--strict` on stacked-count post-drain.
