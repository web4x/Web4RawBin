# R30.53 left-fold-desync — architect diagnosis (confirm of tester root)

**Author:** robbin-architect@WODA.prod robbinTeam2:0.3 · 2026-07-19

## ROOT CAUSE — CONFIRMED (tester RED ba0a2734e + code-measured)
`_mirrorFold` (rb-diff-editor.ts:380-391) maps fold correspondence across the 3 editors by **RAW INDEX**:
```
const srcRanges = this.computeMethodRanges(srcEd.getModel());
const seq = srcRanges.map((r, i) => ({ i, collapsed: !!srcFm.getRegionAtLine(r.start)?.isCollapsed }));
... for each target editor:
  const ranges = this.computeMethodRanges(ed.getModel());
  for (const { i, collapsed } of seq) { const r = ranges[i]; ... }   // ← ranges[i] = raw index
```
Raw-index correspondence assumes the i-th method is the SAME method in every pane. A **green ADD-block** adds a method (e.g. `private.complete.paneTargets()`) to CENTER+REPO but **NOT LOCAL** (it's an addition absent from Local). So Local's method list is shorter/shifted: every method *below* the add sits at a **different index** in Local than in Center/Repo. The mirror then applies Center's method[k] collapse-state to Local's method[k] = the **wrong method** → the actual unchanged method (`private.complete.buffers()`, offender, downstream of the green block) is left un-synced → Local stays expanded → taller pane → downstream 3-pane row-drift. Tester DET-3x: 1/19 shared unchanged methods desync, exactly the downstream-of-add one.

Note: the INITIAL `syncNativeFold` is NOT affected — it folds each editor's OWN unchanged methods via per-side `keepChangeMethodsExpanded(computeMethodRanges(ed), side)` (identity-correct per pane). The defect is SOLELY the cross-editor **index** mapping in `_mirrorFold`, triggered when the add's rebuildCenter → center foldingModel onDidChange → `_mirrorFold('center')`.

## FIX — CONFIRMED correct-by-construction: re-key by method SIGNATURE, not raw index
Map fold correspondence by method IDENTITY (the def-line signature at `r.start`), not position:
- `computeMethodRanges` (or a sibling) must ALSO return the def-line **signature** per range (the text at `r.start`, e.g. `private.complete.buffers()`).
- `_mirrorFold`: build `seq` keyed by signature; for each target, find the method with the SAME signature and apply the collapse-state.
- **Robust to add/remove offsets by construction:** a method absent in a pane (an added method not in Local) has NO signature match → correctly SKIPPED (an added method must not mirror to a pane that lacks it). Downstream methods match by name regardless of index shift.

### Refinements (flag to expert)
1. **Duplicate signatures** (rare — same top-level name twice): key by `signature + ordinal` among same-signature methods, OR accept the unique-name assumption for oosh/bash (`private.x`/`public.y` are unique). Note the assumption.
2. Localized change: `_mirrorFold` + `computeMethodRanges` signature extraction only. The initial `syncNativeFold` is the reference for "correct per-side correspondence" — the mirror should now match it by identity.
3. Nothing deeper: initial fold is per-side-correct; the whole defect is the raw-index cross-editor mapping.

## SECOND CAUSE — CONFIRMED (expert's keepChangeMethodsExpanded clip hypothesis)
The desync is NOT mirror-only — it ALSO fires at INITIAL render via `keepChangeMethodsExpanded` (L319-326). For a GREEN ADD absent in Local (`c.a.length=0`), Local's change-range = `[c.aStart+1, c.aStart + Math.max(c.a.length,1)]` = a **1-line span at the insertion point** (the `Math.max(...,1)` floor synthesizes a phantom line where ZERO local lines actually changed). Overlap `r.start <= e && s <= r.end` with `s=e=c.aStart+1`: if the add sits immediately before the next unchanged method M (`M.start = c.aStart+1`, exactly the bug shape — add then `buffers`), then `M.start <= c.aStart+1 <= M.end` = TRUE → **M excluded from Local's initial collapse → stays expanded**, while center/repo use the REAL added span (not clipping M) → collapse it. Desync at initial render, independent of the mirror.

**FIX #2 (clip-fix) — needed IN ADDITION to the signature-key mirror fix:** in `keepChangeMethodsExpanded`, compute the per-side change-range with the **REAL side length (no `Math.max(...,1)` floor)**; a zero-length side-change (a pure insertion point in that pane changes 0 lines) → EMPTY range → overlaps no method → excludes nothing. Verified: with real length, Local range `[c.aStart+1, c.aStart]` (empty) → `M.start(c.aStart+1) <= e(c.aStart)` = FALSE → M NOT excluded → collapses → synced. Insertion-INSIDE-a-method stays symmetric (center splits it too → both exclude → still synced). Correct-by-construction.

**VERDICT: both fixes required** — (1) `_mirrorFold` signature-key (toggle/mirror path), (2) `keepChangeMethodsExpanded` drop the `Math.max(...,1)` floor so a zero-length add doesn't clip the following method (initial-render path). Signature-key ALONE = half-fix (leaves the initial-render clip). The `Math.max(...,1)` floor may still be wanted for the gutter DECORATION marker — keep it there, but NOT in the fold-overlap computation (split the two uses).

## FIX-A EXACT SPEC (initial-render parity — correct-by-construction; DISTINCT from FIX-B mirror)
**Requirement (PO):** the initial unchanged-method fold classification must be PARITY-consistent across L/C/R — a shared unchanged method collapses in ALL 3 regardless of per-pane change-overlap. The current bug: 3 INDEPENDENT per-pane overlap filters (`keepChangeMethodsExpanded` called separately per side) can DIVERGE — a zero-length add's 1-line phantom clips the following method out of Local's set only.

**Fix = classify the collapsible set ONCE by SHARED IDENTITY, then fold that same set in all 3 (parity by construction):**
1. `computeMethodRanges` returns `{start, end, sig}` per method (`sig` = def-line signature text at `start`). [shared with FIX-B]
2. NEW `computeSharedUnchangedFoldSet(): Set<sig>`:
   - Per pane P∈{local,center,remote}: `methodsP = computeMethodRanges(P.model)`; `changedP` = signatures of methods overlapping a **REAL** change-range in P — using **real side length, NO `Math.max(...,1)` floor**: local `[aStart+1, aStart+a.length]` (EMPTY when a.length=0), center `[span0+1, span1]`, remote `[bStart+1, bStart+b.length]` (EMPTY when b.length=0). Empty range overlaps nothing.
   - `sharedSigs` = INTERSECTION of the three panes' signature sets (method present in ALL 3).
   - `collapsible` = `sharedSigs` MINUS (`changedLocal ∪ changedCenter ∪ changedRemote`) — a shared method is collapsible iff change-free in EVERY pane.
3. `syncNativeFold`: for each pane, collapse exactly the methods whose `sig ∈ collapsible` (found via sig in that pane's ranges). → identical set folded in all 3 = PARITY BY CONSTRUCTION.

**Why correct-by-construction:** (a) the collapsible set is ONE shared set, not 3 divergent per-pane filters → can't fold in C/R but not L; (b) real-length overlap → a zero-length (green add) side contributes an EMPTY change-range → never clips the following method; (c) an ADDED method (sig in center/repo but not local) is not in `sharedSigs` → never collapsed anywhere (correct); (d) a method genuinely changed in ANY pane is in the union → expanded in all 3 (consistent). Localized to `keepChangeMethodsExpanded`→`computeSharedUnchangedFoldSet` + `syncNativeFold`'s per-pane collapse. Shares the sig-extraction with FIX-B; the two are otherwise separate paths (FIX-A = initial classification, FIX-B = mirror/toggle propagation).
