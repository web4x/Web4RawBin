# R30.53 left-fold-desync — architect diagnosis (confirm of tester root)

**Author:** robbin-architect@WODA.prod robbinTeam2:0.3 · 2026-07-19

## ROOT CAUSE — CONFIRMED (tester RED ba0a2734e + code-measured)
`_mirrorFold` (rb-diff-editor.ts:380-391) maps fold correspondence across the 3 editors by **RAW INDEX**:
```
const srcRanges = this.computeMethodRanges(srcEd.getModel());
const seq = srcRanges.map((r, i) => ({ i, collapsed: !!srcFm.getRegionAtLine(r.start)?.isCollapsed }));
... for each target editor:
  const ranges = this.computeMethodRanges(ed.getModel());
  for (const { i, collapsed } of seq) { const r = ranges[i]; ... }   // ← ranges[i] = raw index
```
Raw-index correspondence assumes the i-th method is the SAME method in every pane. A **green ADD-block** adds a method (e.g. `private.complete.paneTargets()`) to CENTER+REPO but **NOT LOCAL** (it's an addition absent from Local). So Local's method list is shorter/shifted: every method *below* the add sits at a **different index** in Local than in Center/Repo. The mirror then applies Center's method[k] collapse-state to Local's method[k] = the **wrong method** → the actual unchanged method (`private.complete.buffers()`, offender, downstream of the green block) is left un-synced → Local stays expanded → taller pane → downstream 3-pane row-drift. Tester DET-3x: 1/19 shared unchanged methods desync, exactly the downstream-of-add one.

Note: the INITIAL `syncNativeFold` is NOT affected — it folds each editor's OWN unchanged methods via per-side `keepChangeMethodsExpanded(computeMethodRanges(ed), side)` (identity-correct per pane). The defect is SOLELY the cross-editor **index** mapping in `_mirrorFold`, triggered when the add's rebuildCenter → center foldingModel onDidChange → `_mirrorFold('center')`.

## FIX — CONFIRMED correct-by-construction: re-key by method SIGNATURE, not raw index
Map fold correspondence by method IDENTITY (the def-line signature at `r.start`), not position:
- `computeMethodRanges` (or a sibling) must ALSO return the def-line **signature** per range (the text at `r.start`, e.g. `private.complete.buffers()`).
- `_mirrorFold`: build `seq` keyed by signature; for each target, find the method with the SAME signature and apply the collapse-state.
- **Robust to add/remove offsets by construction:** a method absent in a pane (an added method not in Local) has NO signature match → correctly SKIPPED (an added method must not mirror to a pane that lacks it). Downstream methods match by name regardless of index shift.

### Refinements (flag to expert)
1. **Duplicate signatures** (rare — same top-level name twice): key by `signature + ordinal` among same-signature methods, OR accept the unique-name assumption for oosh/bash (`private.x`/`public.y` are unique). Note the assumption.
2. Localized change: `_mirrorFold` + `computeMethodRanges` signature extraction only. The initial `syncNativeFold` is the reference for "correct per-side correspondence" — the mirror should now match it by identity.
3. Nothing deeper: initial fold is per-side-correct; the whole defect is the raw-index cross-editor mapping.
