# Sprint 24 — Traceability Skills (OOSH-like TS) — Architecture / Design Decisions

**Author:** robbin-architect · 2026-06-29. Builds on skill-expert's [chain-skills-formalization.md](../../skills/chain-skills-formalization.md) (measured surface) + req's 5 S24 reqs (8c6a7dcb4). Per CMM4 #18: req captured → architect designs → expert implements → tester gates.

**Premise (no greenfield):** the tools already ship — `objectVerb.ts` (generic Object.verb dispatcher + introspect + emitters), `planner-drive.ts`/`CurrentSprint` (pin), `skill-classes.ts` `Chain` (scoring), `generate-sprint-md.ts` (scenario→MD view), `trace-cli.ts`+`trace-audit.ts` (audit). S24 FORMALIZES them as OOSH-discipline skills (self-documenting, method-dispatch, Tab-completable) + wires their chains. The TS method signature + JSDoc stays the SINGLE SOURCE OF TRUTH (`introspect()` already feeds all emitters — protect this DRY win).

## Design decisions (skill-expert's 3 calls — architect owns these)

### (a) Pin/CurrentSprint object shape + planner-drive: SHIM, don't retire (yet)
- **Add a `Pin` object to the objectVerb registry**, wrapping `CurrentSprint`. Verbs (typed, JSDoc'd so introspect/complete/emit all derive): `pin` (= pinCurrent/getThreeSlots), `focus <taskUuid> <?force:boolean>`, `advance`, `hop <hop> <status> <?agent>`, `gate`, `setChain <req> <uc> <class> <method> <impl> <test> <sprint> <task>`, `setNextBacklog <uuid>`, `clearNextBacklog`. This makes the pin verbs introspectable, Tab-completable, emitted to OOSH, and discoverable via `list` — closing the biggest gap (they're ad-hoc in planner-drive.ts today).
- **planner-drive.ts becomes a THIN SHIM, NOT retired immediately.** It delegates each verb to `Pin.<verb>` and prints the same output. Rationale: planner (0.6) + I drove the entire S22/S23 crisis through `npx tsx scripts/planner-drive.ts <verb>` — a hard retire breaks the heaviest user mid-flight. The shim is a **deprecation bridge**: keep ONE sprint, mark deprecated, retire only AFTER `pin <verb>` is live-verified on WODA.prod (Tab-complete + parity). This is the "retire the old path only once the replacement is proven" discipline — shim bridges, then remove.

### (b) Per-object OOSH scripts (chain<Tab> / pin<Tab>), NOT one umbrella
- One OOSH script per registry object: `chain`, `pin`, `velocity`, `scenario`, `rules`, `audit` — each generated by `emitOosh <Object>`, symlinked into `~/oosh/external/`, `#!/usr/bin/env bash` + `script.start "$@"`. This honors the OOSH law **one script = one class** and matches the team's existing muscle memory (`otmux<Tab>`, `hiveMind<Tab>`). Discoverability becomes `pin<Tab>` → its verbs.
- Keep the single `taskChain` umbrella as a **back-compat alias** only (so existing references don't break).
- This also makes the **expert+tester ownership pair** clean (OOSH law): one owner pair per script, one test file per script.

### (c) Emit-drift gate: BOTH layers — pre-commit (DX) + CI (authority)
- **CI gate is the authoritative, un-skippable backstop** (MUST exist): CI runs `objectVerb emitOosh <each>` and `diff`s against the committed script; any drift fails the build. Guarantees `committed OOSH wrapper == emitOosh output` always.
- **Pre-commit hook is the fast-feedback convenience layer**: same diff locally so the author who changed a method signature regenerates BEFORE commit (best DX). But hooks are skippable (`--no-verify`), so CI is the guarantee.
- Defense-in-depth (same rationale as forward-only stripping at server+client): neither layer alone is sufficient — pre-commit can be skipped, CI catches it; CI is slow feedback, pre-commit catches it early. The invariant lives in CI.
