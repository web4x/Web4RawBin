## The 6 items (Tron verbatim intent)

### Item 1 — BUG: drag-to-add broken for NEW/empty diagrams
Dragging elements INTO a NEW diagram STILL doesn't add anything to the diagram. Drop-to-add is broken specifically for new/empty diagrams. **This is a bug (functionality broken) → highest priority.** Route architect(diagnose)→expert(fix)→tester(catch @390). Likely related to R33.5 item-1 (addDiagram) / the diagram model-write path.

### Item 2 — Suppress page scroll on element select+move; keep diagram autoscroll only near boundary
When a diagram element is SELECTED + MOVED, SUPPRESS page (browser) scrolling. ONLY preserve AUTOSCROLL of the DIAGRAM itself when the dragged item goes SLIGHTLY OUTSIDE the diagram boundaries (edge-pan). So: no page scroll during element drag; diagram edge-autoscroll only when the element is dragged just past the diagram edge.

### Item 3 — Recalculate relationships after moving an element
After moving a diagram element, RECALCULATE the relationships → re-route / redraw the connector LINES to the element's new position (connectors follow the moved node).

### Item 4 — Existing PUML rendered as itemviews in the puml folder (STILL incomplete)
Existing .puml files are STILL NOT rendered as itemviews under the puml folder — the puml-folder itemview integration is incomplete. **Connects to deferred R33.1.1 (PUML-code leaf) + R33.5 item-4 (puml enumeration).** Recurring incomplete — consolidate, don't re-fork.

### Item 5 — Action bar INTO the drawer, always, dynamic by selection
Move the ACTION BAR **into the drawer**, directly BELOW the handle bar, ABOVE the diagram/content — ALWAYS present there. Make its contents DYNAMIC by selection:
- diagram-folder selected → 'add diagram'
- class selected → rename / remove-from-diagram / delete / new-class
(Reuse the rb-detail-drawer pattern from R31.4 — action bar as a fixed drawer region below the grab-bar.)

### Item 6 — Selection always drives the action-bar content
Selecting ANYTHING always triggers the action-bar content to change (selection-driven). The action bar reflects the current selection's available actions at all times. **Items 5+6 are tightly coupled — likely one requirement (action-bar-in-drawer + selection-driven contents).**
