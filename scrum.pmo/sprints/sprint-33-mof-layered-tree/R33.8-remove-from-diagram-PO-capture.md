# R33.8 — "Remove from diagram" action (Tron, IMG_4794)

**Tron (device, 13:47, Model-Driven Code Quality):** "i am lacking a 'remove from diagram' button" + "action" (= it's an action-bar ACTION, per the R33.6.5 selection-driven action bar).

## The ask
A **"Remove from diagram"** action in the action bar — when a class/element on a diagram is selected, an action removes it FROM the diagram (the view/add-view), WITHOUT deleting the underlying model element. Consistent with the R33.6.5 selection-driven action bar (contents switch by selection type).

## Connects to an R33.6.5 gap
R33.6.5's spec (Tron round-2, item 5) was: "class selected → **rename / remove-from-diagram / delete / new-class**." But only **"Add to diagram"** actually shipped for class selection (per the R33.6.5 tester gate). So the fuller class-action set — including **remove-from-diagram** — was spec'd but never built; the gate green-passed a partial set. Tron is now asking for the missing remove-from-diagram.

## Scope (req to decide)
- **Minimum (Tron's explicit ask):** add the **remove-from-diagram** action (class-on-diagram selected → action removes its view/add-view from the diagram; model element untouched; connectors re-route/drop; diagram refreshes).
- **Fuller (R33.6.5 completion, flag to Tron):** the rest of the spec'd class-action set — rename / delete / new-class — that also never shipped. Req scopes: do just remove-from-diagram now, OR complete the R33.6.5 class-action set. Recommend: at least remove-from-diagram (Tron's ask); flag the rename/delete/new-class gap to PO/Tron for a follow-up.

## Mechanism (reuse, no fork)
Reuse the R33.6.5 action-bar (ACTIONS_BY_TYPE, selection-driven) — add a "remove from diagram" verb for the class-on-diagram selection → removes the view (inverse of add-view/R33.5 addView) → refresh + rerouteEdges (R33.6.3). Model-store view-removal, prod-safe (the model element/unit stays; only the diagram's view-link drops).
