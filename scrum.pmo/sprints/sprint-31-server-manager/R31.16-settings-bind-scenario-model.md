## The real issue: the Room Settings modal is NOT bound to the room scenario unit
The room IS a scenario unit (`ior:instance:<uuid>@host`); its settings (name, visibility, mode) should be FIELDS of that unit — the editor READS current values from it and WRITES changes back to it (scenario model = source of truth, RawBin core law). Observed in IMG_4709 (Christine Dawood's Room, Tron = non-host member):
- **Name** field shows *"Christine Dawood's Room" as a grey PLACEHOLDER*, not as the actual bound value. A bound editor shows the room's REAL current name as the editable value (or read-only text for non-host), not a placeholder/default.
- Visibility=Public, Mode=Persistent(default) — need to CONFIRM these reflect the room scenario's ACTUAL stored values, not hardcoded defaults.
- Non-host = read-only/Close (by-design from R31.12) — fine, BUT it must still DISPLAY the room's real bound values.

## Direction (SIMPLE — bind, don't hack): make the settings a model-bound editor
- READ: populate name/visibility/mode from the room scenario unit's actual fields (not placeholders/defaults).
- WRITE (host): Save updates the room scenario unit's fields (UPDATE_ROOM_CONFIG → persists to the scenario model / server truth), and the change is reflected back (the model is the source).
- Non-host: shows the real bound values, read-only.
- This is standard model-binding, NOT ad-hoc modal state. If it's "complicated" today, it's because the modal builds ad-hoc HTML with defaults instead of binding to the scenario model.
