# R31.7 durable fix — server must NOT flush the build-owned config-singleton (architect 2026-08-05)
## DIAGNOSIS (confirmed on disk)
Version regression 0.8.54→0.8.46: `scenario/index/c/o/n/f/i/config-singleton-0000-000000000001.scenario.json` is dirty **M** with a VERSION-ONLY diff (`"version":"0.8.54"`→`"0.8.46"`; name/branch/plantumlUrl unchanged). The running server booted at 0.8.46, holds the config unit in memory, and later PERSISTS it back to disk at 0.8.46 — clobbering a build bump to 0.8.54. Then the R31.7 build (start.mjs step 4) regenerates pkg/sw/manifest FROM the dirty 0.8.46 unit → regression. Antipattern = **served-repo real-saves a BUILD-OWNED unit**.
- WRITE CHOKEPOINT (measured): `ScenarioIndex.put(uuid, scenario)` (src/ts/scenario/index-store.ts:43) — `fs.writeFileSync(<uuid>.scenario.json, JSON.stringify(scenario))`. This is the SINGLE disk-write path for every unit. The config-singleton literal appears in server.ts ONLY as a READ (plantumlBaseUrl :1286; /api/config serves BOOT_VERSION not the unit) — so the flush is a VARIABLE-uuid `idx.put()` (a generic save path), which is exactly why a chokepoint guard is the right fix: it blocks EVERY path at once.
## DESIGN — by-construction guard at the ONE write chokepoint (Tron: cannot recur)
Add a BUILD-OWNED exclusion to `ScenarioIndex.put()` — refuse to write build-owned uuids. The config-singleton (version/branch owned by the BUILD, start.mjs) becomes read-only at runtime BY CONSTRUCTION; no server code path can flush it.
```ts
// src/ts/scenario/index-store.ts — in class ScenarioIndex
static readonly BUILD_OWNED_UUIDS = new Set<string>(['config-singleton-0000-000000000001']);
put(uuid: string, scenario: ScenarioUnit): void {
  if (ScenarioIndex.BUILD_OWNED_UUIDS.has(uuid)) {           // R31.7: build-owned + read-only at runtime
    console.warn(`[ScenarioIndex] refused runtime write of BUILD-OWNED unit ${uuid} (config-singleton version/branch is owned by the build; never flushed by the server)`);
    return;                                                   // NO-OP: the server never persists config
  }
  this.invalidateListCache();
  // …existing write…
}
```
### WHY correct-by-construction
- `put()` is the SOLE disk-write for all units → ONE guard blocks ALL flush paths (the 6 current idx.put sites + any future/generic edit/save), no enumeration needed. The antipattern CANNOT recur.
- The build (start.mjs) OWNS config: it bumps `version` + regenerates pkg/sw/manifest; it writes the config unit directly (not through the server's ScenarioIndex.put). The server READS config (plantumlUrl) + serves version from BOOT_VERSION (build-manifest, R31.7 INV-V4) — it never needs to persist the unit.
- WARN (not silent) so any code that TRIES to flush config is VISIBLE in logs (surfaces the offending path without letting it corrupt).
### IMMEDIATE REMEDIATION (expert doing now, orthogonal to the guard)
Restore/bump the SOURCE config unit to the correct version (0.8.55) + rebuild + atomic commit + restart → /api/config==0.8.55, clean tree. The guard PREVENTS the next recurrence.
### GATE
After the guard: the running server can NEVER dirty the config-singleton (any put attempt = warn + no-op); a build bump survives a running server (no clobber); `git status scenario/index/.../config-singleton` stays clean across server operation. Extensible: add any other build-owned singleton to BUILD_OWNED_UUIDS.
