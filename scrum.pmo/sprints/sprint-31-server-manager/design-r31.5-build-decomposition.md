## Open questions → ARCHITECT DECISIONS (build-ready)
- **Peek width:** portrait compartment `min-width: 88vw` (≈12% peek of the next compartment). One CSS var `--rb-peek: 12vw` so it's tunable, not per-snap logic.
- **Snap granularity:** COMPARTMENTS are the snap targets (`scroll-snap-align:start`); BARS are inter-compartment, NOT independent snap points (they ride at a compartment's leading edge). Snaps land on meaningful content, editor `[]|[` / `]|[]|[` / `]|[]` fall out of compartment-align + peek — no bespoke per-snap JS.
- **Mode driver:** CONTAINER-QUERY (`@container`) on the rb-strip's container, orientation media-query as fallback — composes when nested (a strip inside a compartment). Sets `rb-strip[data-mode=landscape|portrait]`.
- **Focus/scroll restoration on mode flip:** the ACTIVE compartment (last-snapped / focused) is preserved across landscape↔portrait — on flip, `scrollIntoView` the previously-active compartment (store its id on the strip).

## BUILDABLE PIECES (incremental, each ships behind the invariant; /trace + editor stay functional throughout)
1. **`rb-strip`** (foundation) — ordered row from a descriptor array `[{id,kind:'compartment'|'bar',content}]`; `data-mode` via container-query; landscape=`display:flex;overflow:visible`, portrait=`overflow-x:auto;scroll-snap-type:x mandatory`. Owns layout+scroll+snap. NO content logic (hosts what descriptors give). Ships behind /trace unchanged (not yet wired in).
2. **`rb-compartment`** — hosts content; `presentation=expanded|bar` attr flips full-content ↔ collapsed strip `|` (icons/verb-buttons). Content+behavior FIXED; only presentation CSS + what's shown branches. (What-bar, changebar, Actions-bar = rb-compartment[presentation=bar].)
3. **Drawer = Details compartment `data-position=inline|bottom`** (THE CRUX + continues the in-flight R31.4 DRY drawer fix = step 0) — generalize `rb-detail-drawer`: a `data-position` attr branches ONLY layout CSS (landscape=inline `[D]` strip segment `position:static`; portrait=`position:fixed;bottom:0` as today). The detail-render flow / scroll / grab-bar / expand-minimize / in-room R30.20 X→chat = ALL shared, untouched. NO "full-width drawer" 2nd component (that fork = the regression Tron flagged).
4. **`rb-snap-nav`** — data-driven bottom nav: one button per COMPARTMENT segment (labels from the strip descriptors); click → `scrollIntoView` that compartment's snap point (native, no JS scroll math). {L,C,R} editor / {What,Overview,Details,Actions} WODA — one component.
5. **Two instances (proves one-model-two-instances):** (a) 3-way editor `[L]|[C]|[R]` = rb-strip `[{C:L},{bar:leftCB},{C:C},{bar:rightCB},{C:R}]`, nav {Left,Center,Right}; (b) WODA `W|[O][D]|A` = rb-strip `[{bar-expandable:What},{C:O},{C:D},{bar:Actions}]`, nav {What,Overview,Details,Actions}. Same infra; only the descriptor array + hosted content differ.

## THE INVARIANT (cross-cutting AC — the acceptance shape)
Presentation state ∈ {bar|compartment} × {landscape|portrait} × {inline|bottom} is a REACTIVE LAYER (CSS + mode attrs) over a FIXED functional core. **AC-INV-PRESENTATION:** the SAME component instance, in ANY presentation combination, passes the SAME functional tests (detail renders, scroll works, expand/minimize, verb-actions fire) — only computed layout/position differs. Any behavior that changes with position/presentation = a DEFECT (the anti-pattern Tron flagged). Tester gates each piece against this at Tron's real viewport (portrait mobile + landscape).
