## ⚠ R31.4 PRESENTATION issues (fix scenario-first — this is UX, not mechanism)
1. **CENTERED content** — the terminal output + prompt are horizontally CENTERED, not left-aligned (a terminal must be left-aligned). Likely inherited text-align/margin:auto/flex-center on the terminal container.
2. **Bespoke fullscreen OVERLAY, not the default drawer** — the terminal opens as its own fullscreen overlay floating over the app, instead of the app's standard detail drawer (rb-detail-drawer) that every other detail view uses. Tron: *"why is the shell an overlay? when its an overlay why is it not in the default drawer?"*
3. **NO CLOSE affordance** — there is no way to close the overlay. Tron: *"how do i close the overlay (no issue if its in the default drawer)."*

## DIRECTION (Tron, clear): render the terminal in the DEFAULT DRAWER
Mount the xterm.js terminal inside **rb-detail-drawer** (the same drawer all detail views use). This gives — for free and consistently:
- the standard **close / minimize / grab-bar** (fixes #3),
- proper **left-aligned** drawer layout (fixes #1),
- **consistency** with the rest of the app (fixes #2 — no bespoke overlay).
The drawer can still expand large; "fullscreen" from the original vision = the drawer expanded, NOT a separate overlay with no chrome.
