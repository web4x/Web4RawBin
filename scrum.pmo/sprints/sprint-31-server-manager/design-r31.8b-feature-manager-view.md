## (2) FeatureManager ADMIN VIEW — `rb-feature-manager-detail`
A detail-view (drawer content) that lets the OWNER manage grants:
- **Read:** NEW `GET /api/feature-manager` (gated `requireFeatureAccess('Feature Manager')`) → returns `[{ uuid, name, icon, allowedUsers:[token…] }]` for ALL Features (scan `ior:class:Feature`). The view lists Features → per-feature its granted users (allowedUsers).
- **Grant control:** per feature, "add user" input → resolve the target to a TOKEN (paste token, or a short LINK-CODE that maps to a token — link-code = a convenience layer, grant-by-token is the stable identity) → `POST /api/feature-manager {action:'grant', feature:<uuid>, token}` (owner-gated). On 200, re-fetch + re-render (the granted user appears; their access flips live — proven at slice-b).
- **Revoke control:** per granted user, a revoke button → `POST /api/feature-manager {action:'revoke', feature:<uuid>, token}` (owner-gated). On 200, re-fetch (the user disappears; their access 403s immediately — revoke-immediate, proven).
- Uses the PROVEN owner-gated `POST /api/feature-manager` (server.ts:979, requireOwnerHttp, INV-F4 root-of-trust). Grant takes the Feature **uuid** (expert is making grant/revoke accept name-OR-uuid; the view has the uuid regardless).
