## ARCHITECT MECHANICAL DIAGNOSIS (robbin-architect 2026-07-27) — measured; device-only factors LABELED (not asserted)
**Q2 — GATING (measured, CERTAIN):** the title-tap is HOST-ONLY. `rb-header.ts:53` `if (showEdit)` binds the title click ONLY when the `show-edit` attr is present; `RoomView.ts:165` renders `<rb-header … ${isHost ? 'show-delete show-edit' : ''}>` → `show-edit` ONLY when `isHost`; `isHost = (this.roomOwnerToken === this.client.playerToken)` (RoomView:74, ownerToken from `msg.room.ownerToken` :57). ⇒ a NON-host member in-room has NO title handler bound at all → tapping the title does nothing. If Tron's failing room resolves `isHost=false` on device (not the owner, OR ownerToken≠playerToken on that device/session), THIS is the root.

**Q3 — MODAL (measured):** the title dispatches `rb-edit` → `RoomView.ts:113` → `openRoomEditor()` = the "Edit Room Config" modal (name / visibility / mode, RoomView:140-159). That is the ONLY room-settings modal; there is NO distinct read-only "room properties" view (grep 'properties' in RoomView = empty). So today the title opens the HOST edit-config modal. If Tron's "room properties" means a view ALL members can open, it does not exist yet.

**Q1 — DOES IT FIRE ON REAL @390 WebKit (bound? emulation-vs-WebKit):**
- Event IS bound (for host): `titleEl.addEventListener('click', …)` (rb-header.ts:55) on `<h2 class="rb-header-title">`, light-DOM, `cursor:pointer` set inline. Binding timing OK (`show-edit` is a STATIC initial attr → render() binds on connect).
- Hit-area is FINE: `.rb-header-title { flex:1; padding:0 4px }` (app.css:170) = wide target, no pointer-events override.
- ★ STRONGEST emulation-vs-WebKit gap (LABELED needs-device-confirm, NOT asserted — R31.13 lesson): a plain `click` on a NON-interactive `<h2>` is the FRAGILE iOS-Safari pattern. iOS WebKit does not reliably synthesize `click` on non-interactive elements (h2/div) from a tap; the common `cursor:pointer` workaround (which they used) is UNRELIABLE across WebKit versions. CORROBORATION: the header's OTHER actions are real `<button data-action>` (rb-header.ts:23-29) → fire fine on iOS; only the title is an h2 with the click-on-non-interactive pattern → Chromium-emulation fires it (false-green), real iOS WebKit may not. This is the classic false-green frame mismatch.

**ROBUST FIX (mechanical, pairs with the PO's Tron-intent answer):**
- Q1 fix (WebKit-fire): make the title a PROPER interactive element — wrap it in/replace with a `<button class="rb-header-title-btn">` (or add `role="button" tabindex="0"` + a `pointerup`/`touchend` handler alongside `click`) so WebKit reliably fires the tap. Kills the h2-click fragility.
- Q2 fix (gating): depends on Tron intent (PO clarifying host-vs-all). Tron verbatim "clicking on the room name in-room should open them" reads UNCONDITIONAL → likely the title should open properties for ALL in-room members. But edit-config is host-only by nature (only host can change name/visibility/mode). Reconcile = either (i) a read-only "room properties" view all members open (host also gets Edit), or (ii) keep host-only edit but that contradicts "unconditional". → PRODUCT decision (PO+Tron), then req sets the AC + I finalize the gate.
- Q3: if Tron wants "properties" (read-only, all members) distinct from "edit config" (host), that's a NEW small view; if "properties"=="edit config", just fix Q1+Q2 gating.
