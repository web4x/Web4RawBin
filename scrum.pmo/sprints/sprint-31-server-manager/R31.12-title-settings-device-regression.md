**Q1 — DOES IT FIRE ON REAL @390 WebKit (bound? emulation-vs-WebKit):**
- Event IS bound (for host): `titleEl.addEventListener('click', …)` (rb-header.ts:55) on `<h2 class="rb-header-title">`, light-DOM, `cursor:pointer` set inline. Binding timing OK (`show-edit` is a STATIC initial attr → render() binds on connect).
- Hit-area is FINE: `.rb-header-title { flex:1; padding:0 4px }` (app.css:170) = wide target, no pointer-events override.
- ★ STRONGEST emulation-vs-WebKit gap (LABELED needs-device-confirm, NOT asserted — R31.13 lesson): a plain `click` on a NON-interactive `<h2>` is the FRAGILE iOS-Safari pattern. iOS WebKit does not reliably synthesize `click` on non-interactive elements (h2/div) from a tap; the common `cursor:pointer` workaround (which they used) is UNRELIABLE across WebKit versions. CORROBORATION: the header's OTHER actions are real `<button data-action>` (rb-header.ts:23-29) → fire fine on iOS; only the title is an h2 with the click-on-non-interactive pattern → Chromium-emulation fires it (false-green), real iOS WebKit may not. ## FINAL FIX SPEC (architect, Tron-ruled: title opens SAME config modal for ALL members; non-host READ-ONLY) — robbin-architect 2026-07-27
**SIZE: SMALL — 2 client files, ~13 lines total, no new view/event, no server change, client-only (no restart). = LEAN-FINISH (expert idle 77%, no rewind needed).**

### FILE 1 — `src/public/ts/components/rb-header.ts:53-56` (Q1 WebKit-reliable + Q2 un-gate)
Replace the `if (showEdit) { … title click … }` block with an ALWAYS-bound, REAL interactive title:
```ts
// R31.12 device-fix (Tron): the room TITLE opens room settings for ALL in-room members (non-host = read-only,
// enforced in RoomView.openRoomEditor). REAL interactive element (role=button + keydown) so iOS WebKit fires the
// tap — was a plain click on a non-interactive <h2> = Chromium false-green, dead on real WebKit.
const titleEl = this.querySelector('.rb-header-title') as HTMLElement | null;
if (titleEl) {
  titleEl.setAttribute('role', 'button'); titleEl.setAttribute('tabindex', '0');
  titleEl.style.cursor = 'pointer'; titleEl.title = 'Room settings';
  const openCfg = () => this.dispatchEvent(new CustomEvent('rb-edit', { bubbles: true }));
  titleEl.addEventListener('click', openCfg);
  titleEl.addEventListener('keydown', (e: Event) => { const k = (e as KeyboardEvent).key; if (k === 'Enter' || k === ' ') { e.preventDefault(); openCfg(); } });
}
```
- Un-gated from `showEdit` → ALL members (Q2). `role=button`+`tabindex`+keydown → WebKit-reliable + a11y (Q1). Reuses `rb-edit` → `openRoomEditor` (host ✏️ still works). The ✏️ button stays host-only (unchanged) — title is the new all-member affordance.

### FILE 2 — `src/public/ts/RoomView.ts` `openRoomEditor()` (Q2 non-host READ-ONLY, safe-by-construction)
```ts
private openRoomEditor(): void {
  const isHost = this.roomOwnerToken === this.client.playerToken; // R31.12: non-host = READ-ONLY (view settings; host edits)
  … build modal (title e.g. `${isHost ? 'Edit ' : ''}Room Settings`) …
  if (!isHost) {                                   // read-only: disable inputs, drop Save, Cancel→Close
    modal.querySelectorAll('input').forEach(el => ((el as HTMLInputElement).disabled = true));
    modal.querySelector('#re-save')?.remove();
    const c = modal.querySelector('#re-cancel'); if (c) c.textContent = 'Close';
  }
  modal.querySelector('#re-cancel')!.addEventListener('click', () => overlay.remove());
  if (isHost) modal.querySelector('#re-save')!.addEventListener('click', () => { … UPDATE_ROOM_CONFIG … }); // host-only send = non-host can NEVER submit
}
```
- Non-host: inputs disabled + Save removed + no save-handler wired ⇒ can VIEW config, cannot submit `UPDATE_ROOM_CONFIG` (safe-by-construction). Host: unchanged edit+save.
- **Belt (verify, not in scope):** the SERVER should already reject `UPDATE_ROOM_CONFIG` from a non-owner (defense-in-depth) — tester/expert confirm the server-side owner check exists.
