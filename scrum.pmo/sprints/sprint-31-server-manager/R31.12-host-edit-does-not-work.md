## RADIO FLICKER-NO-STICK (v0.7.145, Tron device) — ARCHITECT ROOT + FIX (robbin-architect 2026-07-27)
**Progress:** tap now FIRES (id/for + block-row + belt = my fix worked on WebKit). NEW symptom = "flickering but not changing" = check-then-REVERT = state doesn't commit. ROOT = **MULTI-FIRE per tap** (hypothesis 1, the double-handler I flagged in the fix spec):
1. **Belt double-handler** (RoomView.openRoomEditor:159): the `.re-option` row binds BOTH `click` AND `pointerup` → `set()` (checked=true + dispatch change) runs TWICE per tap.
2. **Redundant label** (:148): `<label class="re-option" for="re-vis-X"> … <input type="radio" id="re-vis-X"> …</label>` — the label BOTH WRAPS the input AND has `for=` to it. Classic wrap+for= REDUNDANCY → the browser dispatches the input's click TWICE (the "flicker-then-no-commit" checkbox-style symptom).
- Combined: a single tap fires the radio's activation ~3-4×. On iOS this races → the radio flickers (checks) but the final state does not commit = "not changing".
- **Hypothesis 2 (re-render reset) RULED OUT:** the only re-render is `MSG.ROOM_CONFIG_UPDATED → this.render()` (RoomView:70), which fires ONLY after SAVE (server broadcast). A radio tap sends NOTHING to the server → no re-render on tap. Hypothesis 3 (name-group) RULED OUT: `name="re-vis"`/`name="re-mode"` intact across the id/for rewrite → group works.

## FIX (de-dupe to ONE commit per tap) — TINY, client-only, RoomView.openRoomEditor only
1. **Belt = ONE handler + suppress the native double:** drop the `click` listener; keep ONLY `pointerup`, and `e.preventDefault()` in it (suppresses the synthetic native click that would double via the label). `set()` runs exactly once → `r.checked=true` (native radio-group unchecks siblings) → dispatch `change` → single clean commit.
   ```ts
   modal.querySelectorAll('.re-option').forEach((row) => {
     row.addEventListener('pointerup', (e) => {
       const r = row.querySelector('input[type=radio]') as HTMLInputElement | null;
       if (r && !r.disabled) { e.preventDefault(); r.checked = true; r.dispatchEvent(new Event('change', { bubbles: true })); }
     });
   });
   ```
2. **Remove the label REDUNDANCY:** drop `for=` from the `.re-option` labels (keep the wrap as the padded container; the belt now drives selection, so the native label activation is suppressed → no wrap+for= double). [Alt: keep `for=`, drop the wrap by making the input a sibling — either removes the redundancy; dropping `for=` is the smaller diff.]
- Net: exactly ONE selection per tap → sticks. Keeps native radios (a11y) + the padded tap row.
- **SIZE: ★ TINY** — ~4-6 lines in ONE method (RoomView.openRoomEditor: single belt handler + preventDefault + drop `for=`). Client-only, no server. = LEAN-FINISH (NOT a fork).
- **GATE:** tester REAL WebKit @390 — tap each visibility + mode radio → it SELECTS and STICKS (no flicker/revert) → Save persists the change. Tron device re-confirm.
