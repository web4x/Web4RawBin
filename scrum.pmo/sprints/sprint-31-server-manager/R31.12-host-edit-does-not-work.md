## ARCHITECT DIAGNOSIS — RADIO-SELECT on iOS (robbin-architect 2026-07-27; H1 owner-resolution REFUTED by Tron: fields correct = isHost TRUE)
**Measured:** the config modal's radio groups (`RoomView.openRoomEditor` :148) are NATIVE `<input type="radio">` wrapped in IMPLICIT `<label>` (input INSIDE label, NO `id`/`for`), inside `<fieldset border:none>`, in a dynamically-created overlay modal (`document.body.appendChild`). NO global `appearance:none`/`-webkit-appearance:none`/`pointer-events` reset on inputs (app.css input rules are class-scoped, none touch radios). Host path → inputs ENABLED (the `!isHost` disable block :152 does not run). The overlay's dismiss handler is `e.target===overlay`-guarded (:143) → does not intercept a radio tap.
**ROOT (device-QA, LABELED needs-@390-confirm per R13 lesson — I can't run iOS WebKit):** native radio + IMPLICIT label + dynamically-injected modal = an iOS-WebKit tap-select fragility. The single text field (Name) FOCUSES fine (iOS focuses inputs), but SELECTING a radio via its implicit label association is the fragile part — Chromium-emulation fires it (the v0.7.144 gate was Chromium = false-green AGAIN), real iOS WebKit doesn't reliably toggle the group. SAME false-green FRAME as the h2-title (device-QA catches what emulation passes) — though the mechanism differs (native-radio-label, not h2-click).

## FIX SPEC (robust to the exact iOS mechanism) — `src/public/ts/RoomView.ts` openRoomEditor only, CLIENT-only
Make the option rows EXPLICIT + tappable + WebKit-reliable:
1. **Explicit `id`/`for` association** (not implicit wrap): `<input type="radio" id="re-vis-public" name="re-vis" value="public"><label for="re-vis-public">Public</label>` — explicit `for=` is the iOS-reliable label→control link.
2. **Block, padded tap rows:** each option `display:block; padding:10px 8px; cursor:pointer` (≥44px iOS hit target).
3. **Belt tap handler (WebKit-fire):** after building the modal, for each `.re-option` row add a `click`/`pointerup` that sets its radio `.checked = true` + dispatches `change` — guarantees selection even if the native label-tap is flaky on WebKit. Read `input[name=re-vis]:checked` at Save (unchanged :160-161).
- Keeps native radios (a11y/keyboard) + adds the explicit-for + the tap belt = selects on iOS by construction.
- **SIZE: SMALL** — ONE method (openRoomEditor), ~15-20 lines (rewrite the 2 radio groups' HTML with id/for + block labels + a small per-row tap loop). Client-only, no server, no restart-for-server (client bundle ship + your deploy restart to serve). = LEAN-FINISH (expert idle).
