# R40.22 — Credential/Identity Decoupling + Storage Re-key (design)

**Author:** robbin-architect · 2026-08-11. PO-dispatched ROOT FIX (not containment). Resolves the conflation diagnosed during the PII incident: **`ownerToken` = identity + credential + storage-key in ONE value**. This is the only step that makes token rotation possible without orphaning a user's home. **Design-only — execute nothing.** No secret values in this note.

## Measured constraint that decides the key (decision 1)
- **No universal on-disk stable owner-id exists.** Profile model keys = `uuid,name,phones,emails,addresses,companies,unitLinks` — **NO token, NO device link**; Device keys = `…,ownerToken,…` (only owner link is the token, no `profileUuid`); Room likewise. **0/195 Device + 0/45 Room ownerTokens resolve to a Profile on disk** (the token↔profile link is runtime-only, in-memory `userProfiles` keyed by the token itself).
- ⇒ **Profile-uuid is NOT viable** (not universal — Devices/Rooms/test-homes have no Profile). Use the PO's fallback: a **purpose-built opaque `storageId`**.

## Decision 1 — `storageId`: a non-secret, never-auth identifier (SAFE-TO-LEAK BY DESIGN)
- **`storageId`** = a fresh opaque uuid minted **per distinct owner** (per distinct `ownerToken`). It keys `data/users/<storageId>/`, appears in path strings + unitLinks, and is **NEVER accepted for authentication** (documented invariant). Because it can never authenticate, its appearing in a leaked path string is harmless — re-conflation is **structurally impossible** (the auth path and the storage key are now different value-spaces).
- **The token becomes purely a rotatable auth credential.** A durable mapping `tokenToStorageId` (and the reverse for auth→home) lives in **gitignored runtime** (`data/`, NOT tracked — it contains the token). Rotating a token swaps its entry in that map; `storageId` is unchanged ⇒ the home is untouched.
- Cost = one mapping; benefit = the three roles are now three values, and the storage key is safe-to-leak.

## Decision 2 — BRIDGE, not hard rename (storage dual-validity)
Migrate each home with BOTH paths resolving during transition (the storage analogue of the auth dual-validity): create `data/users/<storageId>/` and make the legacy `data/users/<token>/` resolve to it (symlink/bridge), so a half-run never breaks a read. Rewrite unitLinks token→storageId, verify, THEN converge and drop the legacy-token bridge. Migration is recoverable, not atomic-or-broken.

## ★★ STEP 0 — VERIFIED INDEPENDENT BACKUP of data/users/ (PO hard precondition; the ONLY data-loss step)
The re-key relocates every user's home — the one step tonight where a mistake is DATA LOSS, not a revertable flag/commit. The bridge/hash-parity/idempotent safeguards defend against KNOWN failure shapes; the backup defends against the UNKNOWN one. **No real write until I verify the backup — not that it claims to exist:**
- **(1) NOT `cp -a` / not hardlinked.** `cp -a` inherits hardlinks that write THROUGH to the live tree, so the "backup" mutates with the original and protects nothing — we paid for this lesson earlier this campaign. VERIFY by inode: sample N files, `stat --format=%i` on live vs backup → **inodes MUST DIFFER** (shared inode = hardlink = fake backup). Use `cp` without `-a` (or a different filesystem / tar-and-extract).
- **(2) genuinely INDEPENDENT** — the inode-distinctness from (1) is the proof; optionally demonstrate a source change does not appear in the backup.
- **(3) pre-MANIFEST recorded BEFORE the first write** — data/users/ = 48 homes / 527 files / 9.3M (measured, feasible). Record the **content-hash MULTISET** (sha256 per file, PATH-INDEPENDENT since the migration changes paths token→storageId) + the file count. Afterwards, re-compute → the multiset must be IDENTICAL (every file's content survives at its new path; 0 vanished — PROVEN, not assumed). This is the count-is-not-content discipline applied to files: record the digest set, not just the 527 count.
- **★ I produce my OWN pre-migration content-multiset as the INDEPENDENT reference** (lesson banked at the arm: arrange the independent derivation BEFORE you need it — so post-migration I verify against my reference, not the migration's own manifest). Backup retained until the post-migration multiset check passes.
- **★ MOVING-TARGET (measure-a-stable-state) — PO-refined invariants:** `data/users/` is LIVE (prod server writes as users act), so backup + manifest + migration race with in-flight writes. (i) **PREFER a brief QUIESCE** — seconds to tar 9.3M buys a genuinely consistent reference, and this is the one step where a mistake is data loss. (ii) If quiesce is impractical, the survival invariant is **ONE-DIRECTIONAL, NOT symmetric:** every file in MY reference multiset MUST exist post-migration (missing-from-reference = FAILURE), but files that APPEARED during the window are NOT a failure (extra = expected). An exact-multiset / equal-count assertion would go RED on a legitimate new write and send us hunting phantom data-loss — **for a moving target, symmetry is the bug; the right invariant is directional** (reference ⊆ post). (iii) **★ DELTA SWEEP is a CLEARANCE CONDITION** (reachable ≠ migrated): the bridge keeps window-writes to the old token-path READABLE, so nothing breaks — but they stay keyed by the TOKEN. Before converge + drop-bridge, a delta sweep MUST catch everything created during the window (files still on a token-key path / newer than the snapshot) and migrate them too — else we retire the bridge with stragglers on the old key and quietly RECREATE the very coupling we are removing. I gate bridge-drop on: 0 files remain under any `data/users/<token>/` path.
- **Test residue:** the step-3 unlisted-probe minted an empty throwaway profile (uuid `334825c2…`) — clean it BEFORE the backup/manifest (or explicitly exclude) so it doesn't perturb the 527-count baseline.

## ★ SINGLE-WINDOW PRIMARY (measurement-driven, PO-approved + architect-cleared) + PROVEN ABORT PATH
Dry-run measured on the extracted backup (live untouched): hash-all + move 47 homes + bridge + re-hash = **0.24s**, content-multiset before==after IDENTICAL; +84 unit rewrites ~sub-second → whole migration a few seconds. ⇒ **PRIMARY = ONE quiesce window** (stop → mint 47 storageId → move homes + bridge-insurance → rewrite 84 token-bearing unitLinks (15 distinct segments) + per-file hash-parity → **EXACT multiset match** (my 527-content reference == post; NOT directional — no arrivals, delta-sweep MOOT, no races) → restart). FALLBACK = live + directional + delta-sweep (not needed at 0.24s). Backup verified: tar sha256 45cf26ff + my independent 527-content-hash reference == expert's EXACTLY (two derivations agree) + my 596-entry (527 files/69 symlinks) reference captured; independence by construction (tar.gz archive) + expert inode spot-check.
- **★★ ADDITIVE COPY, NOT MOVE (expert refinement, architect-ENDORSED) — the abort path falls out for free.** COPY `data/users/<token>/` → `<storageId>/`, leaving ORIGINALS BYTE-UNTOUCHED — the originals ARE the insurance (real dirs, both paths resolve; no bridge-symlink, no non-atomic mv/ln window). Cost +7.9MB (trivial). Ordered so failure lands safe: (1) mint storageId + write `tokenToStorageId` (gitignored runtime); (2) COPY each home + per-file hash-verify before==after (ORIGINALS UNTOUCHED); (3) REWRITE the 84 token-bearing unitLinks in scenario units (tracked change, LAST — the riskier half, after data is safe); (4) VERIFY links resolve to `<storageId>` + EXACT multiset == b5ec87fb + no-token-in-tracked-path gate; (5) restart with regrowth-kill code; originals KEPT as insurance (later cleanup, after rotation kills the tokens).
- **★★ PROVEN ABORT PATH (PO hard gate; server-DOWN = no debug-live) — SATISFIED.** Because originals are byte-untouched, at ANY failure ALL reads work (rewritten units→`<storageId>` exists via copy; un-rewritten→`<token>` original exists). ABORT = `git checkout scenario/index` (revert the unitLink rewrites — TRACKED, cleanly revertible) + revert/don't-deploy the regrowth-kill code + restart OLD code → serves originals; `rm` the storageId copies (harmless, gitignored). **ZERO data restore.** PROVEN on scratch (not improvised): simulated crash after 25/47 copies → original-homes multiset UNCHANGED (b5ec87fb == b5ec87fb) — the analogue of the arm's pre-specified instant-revert. **Architect gate: SATISFIED — abort path is written, proven, zero-restore.**
- Note: keeping the original token-dirs as insurance does NOT re-leak — they are GITIGNORED runtime (the credential-in-path concern is the TRACKED unitLinks, which step 3 rewrites); the token-dirs get cleaned post-rotation.

## ★★ THE REWRITE STEP HEALS (root-caused) → verify DECLARED==MATERIALIZED, not raw symlink counts
Scratch bisect (expert + architect): copy-phase symlinks = 69 (faithful) → after the unitLink REWRITE = 70. Cause: `ScenarioIndex.put()` SYNCS the data/users symlink farm from a unit's `unitLinks` (`ensureSymlinkDisk`). Rewriting the 84 File/WebItem unitLinks token→storageId + `put()` MATERIALIZES the declared symlinks at the storageId home — including ones the ORIGINAL token home had left UNMATERIALIZED (pre-existing data-debt, same class as the 36 broken + 11 orphans). **This is a HEAL, not corruption** (architect-verified: room `68d0f039` is declared across 3 homes — 13 units→c117f9fc / 1→063c00d0 / **1→ce981242** — and ce981242's copy +1 == its OWN single declared-but-unmaterialized link; NOT cross-home). The migration reconciles the farm to the declarations (beneficial, zero data loss — content-multiset unaffected, symlinks-only). **State it so `70 != 69` is never misread as corruption.**
- **★ GATE = per-home DECLARED==MATERIALIZED (architect semantics call, option-2 REFINED):** for each storageId home, the MATERIALIZED symlinks must equal the `unitLinks` DECLARED FOR THAT HOME (units whose REWRITTEN path resolves to this `<sid>`), BIDIRECTIONAL: (a) every materialized copy symlink is declared by a unit FOR THIS HOME → catches cross-home injection + spurious; (b) every declared-for-this-home symlink is materialized → catches DROPS. This ALLOWS the legit heal, CATCHES both injection and drop. Rejected: plain "declared in SOME unit" (would let a real cross-home injection pass — a c117f9fc-declared link wrongly landing in ce981242 passes "some unit"); "declared==declared" (doesn't validate put actually wrote the symlink on disk); "heal originals then compare" (mutates the byte-untouched insurance). The raw count-mirror was too strict (compared healed-copy vs unhealed-original) — tightened to DECLARED semantics, not deleted; on a real divergence it still fails.

## Decision 3+4 — the migration (data over live user data → full treatment)
Per owner (idempotent, fail-closed, half-run-recoverable):
1. **DRY-RUN + COUNTS first:** distinct owners, homes under `data/users/`, files per home, the 167 tracked unitLinks token-segments to rewrite. Emit the table; no writes.
2. **Mint** `storageId` for the owner if absent (idempotent: skip if `tokenToStorageId` already has it).
3. **Bridge** `data/users/<token>/` ↔ `data/users/<storageId>/` (both resolve).
4. **Rewrite** the owner's File/WebItem `model.unitLinks` `../data/users/<token>/…` → `…/<storageId>/…`; **prove every link resolves AFTER** (stat the target); **byte-verify file CONTENT unchanged** (hash each file pre/post == equal — no file lost/altered).
5. **DELTA SWEEP + Converge:** BEFORE dropping any bridge, re-scan `data/users/` for files created during the window (still under a `data/users/<token>/` path / newer than the snapshot) and migrate them too. Only when **0 files remain under any token-key path** do all reads route via `storageId` and the legacy-token bridge is dropped. (Reachable-via-bridge ≠ migrated — dropping with stragglers recreates the coupling.)
6. **Kill mint-regrowth at source (4):** `createUserHome(token)` (UserKeys.ts:51) → `createUserHome(storageId)`; `file-unit.ts:74` `roomFsLink` uses `storageId`; the mint (server.ts:1996/2009) passes `storageId`, NOT `playerToken`, into `createFileUnit`/`createWebItemUnit`. New uploads embed the non-secret `storageId` — the migration cannot refill behind us.
- **Fail-closed + idempotent:** every step checks "already done?"; a home that fails any check ABORTS that home (RED), never drops it; the bridge means a half-run leaves all reads valid; re-run completes.

## Decision 5 — the gate that proves it (stub-must-fail + a structural invariant)
- **Post-migration invariants (fail the migration if any breaks):** (a) NO `data/users/<token>/` path remains — every home keyed by `storageId`; (b) **NO tracked unitLinks (or any path string) contains a credential-shaped segment** (scan paths; a token-shaped value in a path = RED) — this is the standing invariant that no NEW path may embed a credential; (c) every File/WebItem link resolves to an existing target; (d) per-file content-hash BEFORE == AFTER (0 files lost/changed); (e) idempotent (a second run is a no-op).
- **stub-must-fail:** feed a home whose file is missing post-move → gate RED (proves it can fail); feed a path still containing a token → invariant (b) RED.
- Wire the credential-shaped-path invariant into `ci:gates` (composes with the field-level `pii-guard`): field-level catches a token in a FIELD, this catches one in a PATH string.

## ★ ORDERING CONSTRAINT (the whole point — state explicitly)
**Storage MUST be keyed by `storageId` BEFORE any token is rotated.** Otherwise rotation orphans the home — the exact trap caught this incident. **Acceptance criterion:** after the re-key, **rotating a token changes ONLY the `tokenToStorageId` mapping (authentication) and touches NO path and NO file** — proven by a post-rekey rotation test whose path/file byte-diff == 0.

## User-experience impact (for PO → Tron)
- **The re-key itself changes NOTHING a user experiences:** during the bridge both paths resolve; after converge the home content is identical, only its directory key changed; auth is untouched (still the token, until its own later rotation). No re-login, no data move visible to the user.
- The user-facing changes are SEPARATE ladder steps: the 116 auth-invalidation (dormant test sessions, ruled acceptable) and the later enrolled-79 rotation (transparent, device-key-gated). **Nothing in THIS design changes user experience** — flagged so PO can tell Tron the root fix is invisible to users.
