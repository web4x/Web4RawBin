# R40.81 Slice-3 flip — ROLLBACK RECOVERY PROCEDURE (robbin-expert, 2026-09-06)

Deliverable required BEFORE the PO flips the default (architect a14520128, rollback condition 3). Rollback model = PO's
**bounded-window (b)**, NOT dual-write (a 2nd live store would violate the one-store law). This is the pre-written procedure.

## The four conditions (architect), and how this build meets them
1. **model-store FROZEN / read-only at flip.** At flip, `MODEL_STORE_SOURCE=scenario-index` → the ONE `ModelStoreLocator`
   routes BOTH reads AND writes to scenario/index. model-store receives NO new writes (coupled — writes follow reads). It
   is frozen by construction, not by convention. Do NOT delete it (Slice-3 deletion is a separate later step).
2. **The risk, named precisely.** Rollback (flip back to `model-store`) makes any model-unit WRITE made during the
   scenario-index window INVISIBLE to /model — because those writes landed in scenario/index, not model-store. The data is
   **NOT destroyed** (it is in scenario/index) and is **re-migratable forward** (flip back to scenario-index → it reappears).
   The only loss is visibility-while-on-model-store. No corruption, no split-brain (the locator guarantees read==write store).
3. **Recovery procedure (this doc).**
   - **Mark the flip instant.** Record `FLIP_TS` (UTC) when the PO sets `MODEL_STORE_SOURCE=scenario-index` + restarts.
     (Also record the pre-flip scenario/index model-unit set — e.g. `find scenario/index -name '*.scenario.json' -newermt` baseline,
     or the committed HEAD sha at flip, whichever is simpler; the sha is cleanest since writes are committed.)
   - **IDENTIFY the post-flip delta** (model units written to scenario/index during the window): model-unit shard files
     (ior:class:ModelElement / Diagram / Folder-model / etc.) in `scenario/index` with mtime > FLIP_TS, i.e. NOT present in
     model-store OR differing from model-store's copy. Concretely: diff the ModelElement/Diagram/model-Folder set of
     scenario/index against model-store (byte + presence); the delta = units created/modified via the coupled write path
     during the window (createElement, add-view, add-diagram, createFolder, import-puml, generate-project, rename, etc.).
   - **ROLL BACK (option A — preferred, zero data motion):** flip `MODEL_STORE_SOURCE` back to `model-store` + restart. /model
     reverts to the pre-flip model-store state. The delta stays in scenario/index (safe). When the flip is re-attempted, the
     delta is already in the target → reappears. NOTHING to re-apply if we simply roll forward again later.
   - **ROLL BACK (option B — if we must STAY on model-store and keep the delta):** copy each delta unit's `<uuid>.scenario.json`
     (+ `.content` sidecar for File units) from `scenario/index/<shard>` into `data/model-store/index/<shard>` (byte-copy,
     read-back-verify — the SAME relocate primitive Slice-1 used, reverse direction). Then flip to model-store. This re-homes
     the window's writes into the frozen store so no visibility is lost.
4. **Window bounded by exit condition.** The scenario-index window is OPEN only until ALL hold: (i) tester `r4081c` PAIR-2
   regression GREEN on the flipped build; (ii) INV-DATA asserts read==write store PER UNIT (the locator makes this true by
   construction, but assert it live); (iii) an observation period the PO sets. On all-green → the flip is permanent-track
   (Slice-3 deletion + flag/lint removal follow). On any RED in-window → roll back per option A. The window is NOT indefinite.
