## Task Description
Today: req-eng authors `requirements.md` markdown by hand. Planner authors
`planning.md` markdown by hand (with at-a-glance symbols I maintain). Tron's
S17 vision lands these as **scenario units** — every Requirement is a
`requirement:<uuid>.scenario.json` in the index, every planning view is
generated by the ViewGenerator from Task instances. T137 is the role
self-update that closes the gap: req-eng + planner LEARN this model and
update their SKILL.md so future work flows through scenarios.

**Planner deltas (specific to me):**
- **Read** scenario.json units for state (instead of grepping markdown)
- **Write** Task scenario units via Task verbs (T133 FSM) when standing up new tasks (instead of hand-writing the markdown checklist)
- **Trust** planning.md as a GENERATED view (don't hand-edit — edit the underlying Task units' `model.status` via T133 verbs, then regenerate)
- **Maintain** at-a-glance symbols by ensuring `model.status` is current (symbol legend derives from status per T133)
- **Walk chains** via IOR.resolve() (T127 + T134 TraceLink), not via grep
- **Stand up new tasks** by creating Task scenario.json (with proper v4 uuid per #17) then regenerating views — task .md file becomes a generated view

**req-eng deltas:**
- **Write** Requirement scenario units (with verbatim Tron quote in `model.quote`) instead of hand-editing requirements.md
- **Cross-link** to Tasks via TraceLink units (T134)
- requirements.md becomes a generated view of all Requirement units owned by the Sprint
- **Anchor** Tron quotes by capturing into scenario JSON, not just markdown
