## 1. Storage

### Scenario Index (canonical)

```
scenario/index/<c1>/<c2>/<c3>/<c4>/<c5>/<uuid>.scenario.json
```

Where `c1-c5` are the first 5 hex chars of the UUID (hyphens stripped). Example:
```
scenario/index/4/7/1/b/9/471b9c4a-378f-4e56-a990-28f82a998b80.scenario.json
```

**Unit shape:**
```json
{
  "ior": "ior:class:<Type>",
  "model": {
    "uuid": "<v4-uuid>",
    "name": "<display name>",
    "tasks": ["ior:instance:<uuid>", ...],
    "...": "type-specific forward arrays"
  },
  "ownerIor": "ior:instance:<parent-uuid>"
}
```

**9 types:** Sprint, Requirement, Task, UseCase, Class, Method, Implementation, Test, TraceLink.

**`ScenarioIndex` class** (`src/ts/scenario/index-store.ts`): `put(uuid, unit)`, `get(uuid)`, `has(uuid)`, `list()`, `remove(uuid)`.

### Generated Views

**sprints.json** — Symlink tree for file-browser navigation:
```
scenario/sprints.json/sprint-17-scenario-units/task/task-124-architecture.scenario.json
  → symlink to ../../index/<prefix>/<uuid>.scenario.json
```
Generated by `generate-sprint-md.ts` / `regenerate-views.ts`.

**sprints.md** — Rendered HTML + Markdown views:
```
scenario/sprints.md/class/<uuid>.md
scenario/sprints.md/requirement/<uuid>.md
scenario/sprints.md/overview.md
```
Generated by `regenerate-views.ts` using `ViewGenerator` + `ViewTemplateRegistry`.

## 2. Pipeline Scripts

| Script | Purpose | When to run | Idempotent |
|--------|---------|-------------|-----------|
| `migrate-to-scenario.ts` | Parse scrum.pmo markdown → create scenario units | After new sprint/task/req files created | Yes |
| `populate-forward-refs.ts` | Fill forward arrays (tasks[], useCases[], classes[], methods[], implementations[], tests[]) from markers + heuristics | After migration or new [impl/test:uuid] markers added | Yes |
| `fill-source-locations.ts` | Populate model.sourceFile + model.sourceLine from [impl/class/uc/test:uuid] markers in source | After source code changes with markers | Yes |
| `strip-back-refs.ts` | Remove prohibited backward fields (Task.requirements, UC.tasks, etc.) | After any pipeline that might create back-refs | Yes |
| `regenerate-views.ts` | Generate sprints.md HTML/MD views + sprints.json symlinks from scenario index | After any scenario unit change | Yes |
| `generate-sprint-md.ts` | Generate sprint-specific symlink trees in sprints.json | After sprint/task unit changes | Yes |
| `trace-remigrate.ts` | Re-run migration with fixes (dirty names, missing fields) | One-shot data repair | Yes |
| `trace-audit.ts` | Validate: orphans, back-refs, cardinality, 7-hop reachability | CI gate / after any change | Yes (read-only) |
| `rule-pair-check.ts` | Verify package.json version = sw.js CACHE_NAME | Pre-commit hook | Yes (read-only) |

### Canonical Run Order

```
1. migrate-to-scenario.ts     (source markdown → scenario units)
2. populate-forward-refs.ts    (fill forward arrays from markers)
3. fill-source-locations.ts    (add sourceFile + sourceLine)
4. strip-back-refs.ts          (clean prohibited backward fields)
5. regenerate-views.ts         (generate symlinks + MD/HTML views)
6. trace-audit.ts --strict     (validate everything — CI gate)
```

Steps 1-5 are idempotent and can be re-run safely. Step 6 is read-only validation.

## 3. Serving

### /api/trace (full graph)
`server.ts:435` — Builds `TraceGraph` via `scanRepo()` (parses scrum.pmo markdown), overlays scenario index titles + Class/Method/Implementation/Test forward arrays. Returns `{objects: FlatObject[], broken: string[], issueCount: number}`.

### /api/trace/children/<uuid> (lazy per-node)
`server.ts:537` — Reads ONE unit from scenario index, returns its forward children per `SCENARIO_FWD` or `TRACE_FWD` (query param `?mode=trace|scenario`). Falls back to scanRepo if scenario index has empty arrays.

### /api/trace/sprints (navigation roots)
`server.ts:501` — Returns all Sprint units sorted by `model.number`.

### /api/trace/roots (chain roots)
`server.ts:519` — Returns all Requirement units with `hasChildren` flag.

### /trace browser (client)
`rb-trace-tree.ts` — Tree component. Two modes:
- Full-graph mode: loads entire graph from `/api/trace`, renders from `TraceGraph` in memory
- Seed mode: lazy-loads per-node from `/api/trace/children/<uuid>`

`rb-*-detail.ts` (7 files) — DetailView components per type. Render from graph object + fetch additional data via `fetchDetailData()`.
