## The hidden write the token-scan CANNOT see (the RED)
A model-unit **EDIT** writes to `data/model-store/index` via a path that contains NO `MODEL_STORE` server token — so r4081d structurally cannot catch it. The store literal lives in the CLIENT; the server write route is store-agnostic:

1. **Client hardcodes the store** — `src/public/ts/trace/rb-detail-drawer.ts:130`: for a model unit the ✎ Edit action builds `scenarioEditorHref(u, 'data/model-store/index')` → `/edit/data/model-store/index/<shard>/<uuid>.scenario.json`. (Comment `detail-children.ts:68` states the pre-migration rationale — "Edit must target their ACTUAL store" — a truth the flip INVALIDATES.)
2. **Editor saves via a generic route** — `src/public/ts/edit.ts:70`: `PUT /api/files/<that relPath>`.
3. **Server writes the client path raw** — `server.ts:3694-3707`: `PUT /api/files/` resolves `wRoot = RepoRegistry.resolve(repo)` (default = rawbin root) and calls `writeFile(relPath, …, wRoot)` → writes `<rawbin>/data/model-store/index/<shard>/<uuid>.scenario.json` = **the model-store**. Overwrite-only, but an existing model unit's file EXISTS there → overwrite succeeds. **No `MODEL_STORE` token, no locator — the store choice came from the client href.**

**Post-flip impact:** model units READ from scenario/index but this ✎ Edit WRITES to model-store → the edit is invisible to the live view = **split-brain**. If model-store is FS-frozen read-only (condition 1), the PUT fails instead → ✎ Edit **broken for every model unit** (fail-closed, but still a defect that must be handled, not shipped silently).

**Why the lint missed it (the general lesson):** r4081d scans the `MODEL_STORE` **token** in server.ts. This is **necessary-not-sufficient** (same shape as isModelUnit for mof-m1). The real hazard is "a model-unit WRITE not through the locator"; a client-supplied store path through the store-agnostic `/api/files` route is one such write with zero server token to scan. A fourth evasion class beyond the PO's list (dynamic-path / runtime-string / aliased-import / second-const): **client-supplied path + generic file-write route.**

## Fix direction (for expert/PO to route — not a full design)
1. **Model-unit ✎ Edit must not hardcode `data/model-store/index`.** Drop the storeDir override at rb-detail-drawer.ts:130 so model edits resolve the locator-consistent store, OR (structural, preferred) route model-unit edits through the server MODEL write path (UnitController → `dirFor`), not the generic raw `/api/files` write. Model units should not be editable via the store-agnostic file route at all post-migration.
2. **Extend the gate's SCOPE to this hazard class** (token-scan alone is incomplete): also assert (a) 0 client-side model-store path literals (`data/model-store` / `model-store`) in `src/public`, and (b) `/api/files` PUT refuses (or locator-routes) a model-store relPath. Scan the HAZARD ("a model-unit write not through the locator"), across BOTH the server token AND the client-href/generic-route surface.
3. Update the stale `detail-children.ts:68` comment (its "ACTUAL store = model-store" premise dies at the flip).
4. Re-gate (r4081d + the extended client/route check GREEN) → THEN flip.

## Verdict
**RED — do not flip.** The coupling of the 6 server sites is sound; the migration is not yet split-brain-safe because the model-unit edit path writes to model-store outside the locator and outside the lint's reach. This is the pre-flip gate doing exactly its job: catching a non-transparency BEFORE the irreversible-direction change.
