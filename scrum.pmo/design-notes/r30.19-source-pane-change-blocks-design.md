## Measured substrate (rb-diff-editor.ts)
- `renderCenterChangeBlocks` (37c9694c): `deltaDecorations` on **edCenter** for each `conflicts[]` hunk → `Range(span[0]+1,1, span[1],1)`, `isWholeLine`, `className: de-block-${c.kind}`; ids tracked in `_blockDecoIds`.
- `Conflict{ a, b, aStart, bStart, span, kind, ... }` — `aStart`/`bStart` = 0-indexed START line of the hunk in Local/Repository; `a`/`b` = the hunk's lines on each side.
- Module-level `CONFLICT_PALETTE`/`conflictColor(c)` (R30.16, classify-at-source `kind`) drive the `de-block-{conflict|resolvable|change}` CSS colors — the SAME classes the ribbons color-match on.

- Decorations are LINE-anchored (not pixel-Y) → they move with content + viewZones automatically → NO off-by-one (unlike the ribbon Y-math R30.17 had to pin).

## Design — Method `RbDiffEditor.renderSideChangeBlocks` (NEW)
Mirror `renderCenterChangeBlocks` onto the two SOURCE editors, origin-gated, SAME class → same color as center + ribbon by construction:
```ts
private renderSideChangeBlocks(): void {
  if (!this.edLocal || !this.edRemote || !this.monaco) return;
  const m = this.monaco;
  const live = this.conflicts.filter(c => !this.dismissed.has(c.id));
  // LEFT (Local) — only hunks with local content (a>0)
  const lDecos = live.filter(c => c.a.length > 0).map(c => ({
    range: new m.Range(c.aStart + 1, 1, Math.max(c.aStart + 1, c.aStart + c.a.length), 1),
    options: { isWholeLine: true, className: `de-block-${c.kind}`, linesDecorationsClassName: `de-gutter-${c.kind}` },
  }));
  this._lBlockDecoIds = this.edLocal.deltaDecorations(this._lBlockDecoIds, lDecos);
  // RIGHT (Repository) — only hunks with remote content (b>0)
  const rDecos = live.filter(c => c.b.length > 0).map(c => ({
    range: new m.Range(c.bStart + 1, 1, Math.max(c.bStart + 1, c.bStart + c.b.length), 1),
    options: { isWholeLine: true, className: `de-block-${c.kind}`, linesDecorationsClassName: `de-gutter-${c.kind}` },
  }));
  this._rBlockDecoIds = this.edRemote.deltaDecorations(this._rBlockDecoIds, rDecos);
}
private _lBlockDecoIds: string[] = []; private _rBlockDecoIds: string[] = [];
```
- **Same `de-block-${c.kind}` class as center** → color-matches center + ribbon BY CONSTRUCTION (single palette source, no independent classification — the R30.16 classify-at-source guarantee extends free to the sides).
- **Origin-aware (reuse R30.17):** left-only change (`b.length===0`) → Local block only; right-only (`a.length===0`) → Remote block only; both-sided → both. This matches the ribbon coverage (R30.17 gated bands the same `a>0`/`b>0`), so **block-coverage == ribbon-coverage** (no block without its ribbon, no ghost).
- **No off-by-one:** decorations are line-anchored at `aStart`/`bStart` (0-idx → +1 for Monaco's 1-idx, same pattern as center) — Monaco moves them with viewZones, so they land on the correct source lines with no Y-pin needed.
