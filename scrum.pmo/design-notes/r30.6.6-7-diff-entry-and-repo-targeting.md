## R30.6.6 — reaching the diff editor (Diff tab/mode in /edit)
**Measured wiring:** `rb-editor-layout` has `activePanel` (tree/editor/preview) + a **mobile-only** tab bar (`.el-tabs` with `.tab-btn[data-panel]`). Desktop uses a split layout. `rb-editor-toolbar` has a `#tb-mode` button dispatching `mode-change {mode}` (an existing mode mechanism). So Diff must be reachable in BOTH form factors — reuse both hooks rather than inventing a route.

**Design (recommended — the tab/mode, not a separate /diff route):**
- Add `'diff'` to `RbEditorLayout.activePanel`.
- **Mobile:** add a `📊 Diff` `.tab-btn[data-panel="diff"]` to `.el-tabs`; existing `showMobilePanel` switches to it.
- **Desktop:** add a Diff entry via the toolbar `mode-change` (a `diff` mode) or a dedicated `📊 Diff` button — when active, mount `rb-diff-editor` full-width in place of the editor/preview split.
- `edit.ts` mounts `<rb-diff-editor>` lazily on first Diff activation (like it wires `rb-file-tree`/`rb-code-editor`), passing the current file as the initial Left side.

**Methods (name-matching):**
- `RbEditorLayout.showDiff` — reveal/mount the diff panel (extend `applyState`/`showMobilePanel` for the `'diff'` case). Class **RbEditorLayout REUSE** (existing unit).
- (edit.ts wiring is glue under `showDiff`; no separate chain method needed unless req wants one for the mount.)

Why the tab/mode over `/diff`: reuses the existing `activePanel`+`mode-change` plumbing and the shared editor chrome (toolbar/back-nav/file-tree); a separate route would duplicate all of it.

## R30.6.7 — target the OOSH repo safely (not RawBin's PROJECT_ROOT)
**Problem:** GitApi + the file tree currently root at `PROJECT_ROOT` (RawBin). The diff tool must operate on the **OOSH repo** (Tron's version issue). Need a safe way to select a *different* repo root.

**Design — allowlist of repo KEYS (not client-supplied paths):**
The client sends a repo **key** (`?repo=oosh`), never an absolute path. The server maps the key → a configured absolute root from a server-side allowlist. Unknown key → 400. This removes client path-abuse entirely; traversal *within* a root is still blocked by the existing `safePath` (server.ts:505-507).

- **New Class `RepoRegistry`** (single source of the security-critical allowlist; shared by GitApi + the files handler):
  - `RepoRegistry.resolve(repoKey): string | null` — return the allowlisted absolute root for the key, else `null`. Config: `{ rawbin: PROJECT_ROOT, oosh: <abs OOSH repo root> }` (from env / a `repos.json`; ops configures the OOSH abs path).
  - `RepoRegistry.list(): {key,label}[]` — for a repo picker in the diff UI.
- **GitApi** (in-build): `GitApi.ROOT` becomes per-request — resolved via `RepoRegistry.resolve(req.repo)`; `branches`/`commits`/`fileAtRef` run with `cwd = resolvedRoot`; `safePath` resolves within it. Ref allowlist `^[\w./-]+$` unchanged.
- **Files** (`GET /api/files/`): accept optional `?repo=<key>` → `RepoRegistry.resolve` → `readDir`/`readFile` rooted there. Default `rawbin` when absent (back-compat, R30.5 unaffected).
- **`RbFileTree`** (client, REUSE 0916d007): new method **`RbFileTree.setRepo(key)`** — set a `repo` attribute + reload; `loadDir` appends `?repo=<key>`.
- **`rb-diff-editor`:** a repo selector (global or per-side) sourced from `RepoRegistry.list()`; passes the chosen key into `loadSide`/`pickFile`/`pickRef` so both the file-chooser and git ops target the same repo.

**Security invariants (mandatory):**
1. Client supplies a KEY only; the absolute path lives server-side in the allowlist. Never resolve a client-supplied absolute path.
2. `safePath` still applies *within* the resolved root (no `..`, no leading `/`, `resolve(root,p).startsWith(root+sep)`).
3. Read-only across all repos (git `branch`/`log`/`show`, `readDir`/`readFile`); no writes to a non-default repo unless explicitly allowlisted for write.
4. Default remains `rawbin`=PROJECT_ROOT → R30.5/existing callers unchanged.
