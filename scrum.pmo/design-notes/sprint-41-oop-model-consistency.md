## ★ CLEAN-CLASS TS SHAPE (ruled 2026-09-13 w/ expert+PO; reusable for File/Folder/Repository/Project)
A modelled class spans server (fs/crypto) + client (DOM) but a TS instance cannot. Shape = **ONE shared class that produces DATA, not effects** (crypto/fs-free AND DOM-free); side-effects live in THIN ADAPTERS the class delegates to.
- `renderSelf()` → returns a **view-model** (pure), NOT DOM — the client thin view adapter renders it.
- `moveTo(target)` → expresses a **command** (pure intent) — the client thin transport adapter dispatches it.
- SERVER adapter = persist/create/hash/fs (+ create-time guards); CLIENT adapter = DOM-render(view-model) + transport(command). The class OWNS behavior (pure); adapters EXECUTE effects.
- Aligns with the 41.4 MVC kernel: the shared class IS the Model (state+IOR-keyed change-event+pure behavior); the thin client adapter IS the View. So 41.1-File and 41.3-observer are the SAME object.
- ★ **The IOR is a VALUE-OBJECT, not a string or a free fn** (PO no-shim ruling + expert): an `Ior` value-object (shared, pure) OWNS compose + parse-goal + GUARD#2; `File.ownIor()`/`Folder.ownIor()` = `Ior.for(class, origin, uuid).toString()` (single format owner, NO dup, NO shim). GUARD#2 (empty-origin THROW) lives in `Ior` construction = by-construction (cannot build an Ior without origin; failable gate stays RED). `composeUnitIor` free-fn DELETED same-increment (knowledge collapses INTO Ior, never wrapped). FOLLOW-UP: `Ior.parse` collapses `parseFederatedIor` (one format owner, no compose/parse drift) — own increment (federation consumers).
