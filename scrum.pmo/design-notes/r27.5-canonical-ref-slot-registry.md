# R27.5 — Canonical Ref-Slot Registry (design)

**Author:** robbin-architect · 2026-07-01. PO-endorsed. The correct-by-construction fix for the R27.4 slot-misses (ownerIor + Test.methods) AND the 2207 audit walk-gaps — ONE registry so migrations, `trace:audit`, and repair-reasserts all scan the SAME complete slot set. Slot-miss becomes impossible by construction. Folds in the R27.5 audit-calibration.

## The principle
Every place a unit-uuid can live is declared ONCE in `REF_SLOTS[unitType] = { forward[], back[], cross[] }`. No migration/audit/repair hand-lists slots again — they import the registry. `CANONICAL_FORWARD` (today's reachability walk) becomes a DERIVED subset: `forward` only. This is *pin-correctness-explicitly*: an explicit reviewed allow-list, never a name-heuristic ("any uuid-shaped field").

## CRITICAL distinction the data forced (measured across the whole graph)
A uuid-shaped field is NOT automatically a graph edge. Empirically there are THREE kinds — the registry must classify each, because miscategorizing floods the audit with false dangling OR misses real edges:
- **SELF / EXCLUDE:** `uuid` (the unit's own id).
- **TOKEN / EXTERNAL-ID — EXCLUDE (uuid-shaped but NOT unit refs):** `ownerToken`, `uploaderToken`, `deviceId`, `token`, `ownerToken`. Evidence they're not edges: Device.`ownerToken` DEAD:195/195, File.`uploaderToken` DEAD:71, Room.`ownerToken` DEAD:30 — they "never resolve" because they're auth tokens, not units. Including them = ~500 false dangling.
- **GRAPH EDGE — INCLUDE (unit→unit), even when the field name isn't `ior`:** e.g. `testUuid` (TestCase→Test, 1023 live), `roomUuid` (File→Room, DEAD:8 = real dangling), `parent`, `@ownerIor`. Name ≠ kind — classify by "does the value denote a scenario UNIT".

## How the three consumers use it
- **`trace:audit`:** dangling scan = for every unit, every slot in `REF_SLOTS[type].{forward,back,cross}` must resolve (excluding token/self). Reachability walk = seed Requirement **AND Sprint** roots, traverse `forward` only. This alone drops 2207 → the true residual (Test▸testCases + Sprint-roots fix the ~1400 walk-gap; the token-exclusion drops the ~500 false). What remains = real dangling debt (e.g. Method`implementation` DEAD:51, Test`parent` DEAD:32, Test`verifies` DEAD:12) — surfaced honestly for a repair pass.
- **Migrations/repairs (R27.4-style):** repoint over `REF_SLOTS[type]` (ALL edges, fwd+back+cross) — so `Test.methods`/`@ownerIor` back-edges are never missed. The gate = "0 dead refs across all REF_SLOTS", not per-touched-slot.
- **Post-apply reassert:** iterate REF_SLOTS — and per the circular-tool lesson, at least one verifier runs an INDEPENDENT tool over the same registry (not the migration's own report-mode).

## Sequencing & scope
1. Ship `REF_SLOTS` + refactor `CANONICAL_FORWARD` to derive from it (+ add Test▸testCases, seed Sprint roots) → the 2207 metric becomes truthful.
2. Re-measure the true dangling residual (registry-complete scan). That residual = real debt → its own repair item (R27.6?), gated delta-vs-absolute until cleared.
3. The lying-marker + duplicateClasses + orphan-Method checks (R27.2/R27.4) all move to registry-based scanning — uniform.
