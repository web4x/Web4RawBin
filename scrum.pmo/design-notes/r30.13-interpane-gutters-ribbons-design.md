## Measured substrate (rb-diff-editor.ts, Class RbDiffEditor 18165081)
- `.de-panes` = flex row of 3 `.de-pane` (local|center|remote), 1px gap; editors `edLocal|edCenter|edRemote` (IntelliJ column order, center=RW Result).
- `.de-accept-bar` (renderMergeGutter :240-255) = the bottom bar to REPLACE; inserted `after('.de-panes')`.
- `Conflict{id, a:localLines, b:remoteLines, pick, span:[Result line range]}` — has the RESULT range; SOURCE line ranges come from the imported `diffIndices` (vendor/diff3).
- `syncScroll3` (e3431e87) uses `editor.onDidScrollChange` → the hook to keep ribbons aligned on scroll. Monaco line→Y via `getTopForLineNumber(n) - getScrollTop()`.
- `acceptChange(id, side)` (843d79d4) already pulls a side into CENTER + re-renders → REUSE for the gutter icons.

## Design — 2 inter-pane overlay layers + ribbon SVG + nav
Insert TWO absolutely-positioned overlay layers into `.de-panes`, one per inter-pane gap:
- **Gutter A** (Local ↔ Result), **Gutter B** (Result ↔ Repository) — each a slim (~28-40px) full-height SVG+icon layer over the 1px gap.
Each holds, per change (row-aligned to the change's Y): **action icons** + **connector ribbon**.

### (1) Inter-pane action gutters — Method `renderInterPaneGutters` (NEW) — THE DESKTOP FIX
Replace `.de-accept-bar` with per-change icon rows positioned at each change's Result-row Y:
- **Left gutter (A):** ✕ (ignore) + ≫ (take Local→Result) → `acceptChange(id,'left')`.
- **Right gutter (B):** ≪ (take Repo→Result) → `acceptChange(id,'right')` + ✕ (ignore).
- **Magic-wand** icon INLINE at each CONFLICT row → auto-resolve (per-conflict smart merge / `applyAllNonConflicting`).
- ✕ ignore = dismiss the change's arrows (mark handled in gutter state; no CENTER change) — reuse `acceptChange` semantics or a local dismissed-set.
- Icons re-position on scroll/resize/`rebuildCenter` (spans move). Works phone + desktop (fixes the invisible-desktop bar). `renderMergeGutter` (e24dc98a) is RE-SCOPED (impl-edit): keep its in-CENTER line-decorations/glyphs, DROP the bottom bar (superseded by this).

### (2) Connector ribbons — Method `renderConnectorRibbons` (NEW)
Colored diagonal FILLED SVG shapes in each inter-pane gutter linking a changed block in the SOURCE pane → its landing rows in Result:
- Endpoints: source line range (Local for Gutter A, Remote for Gutter B — derived via `diffIndices(local,remote)` / `diffIndices(base,side)`) and Result `span`; Y via `getTopForLineNumber - getScrollTop()` per editor; draw a quadrilateral (source top/bottom edge → Result top/bottom edge).
- **Color:** blue = non-conflict change, green = resolvable, red/brown = conflict/deletion (map from Conflict type + pick state).
- **Alignment:** SVG `<path>` per change; **redraw on scroll** (register in `syncScroll3` via `onDidScrollChange`, throttled with `requestAnimationFrame`) + on resize + on `rebuildCenter`. Self-contained: the ribbon renderer computes source ranges via `diffIndices` internally (NO change needed to R30.12's computeTwoWayHunks — keeps R30.13 decoupled).

### (3) Change counter + nav — Method `jumpToChange` (NEW)
Toolbar (`.de-toolbar`): **"N changes, M conflicts"** (from `conflicts.length` + `conflicts.filter(true-conflict)`) + ▲/▼ buttons → `jumpToChange(±1)` reveals the prev/next change's Result line (`edCenter.revealLineInCenter` + scroll-sync).
