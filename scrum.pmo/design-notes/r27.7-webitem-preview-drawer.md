Not reported as "done" until the units exist.** Builds on the existing preview lineage — REUSE those Classes, don't mint dups (R27.2 reuse-by-name): `ContentPreviewer`, `RbDetailDrawer`, `RoomView`, `WebItem` (R19.63/64/73/78/79/83/86/87/93, R20.1/24, R25.2). The regression BUG11/BUG13 (URL buttons dead / .url doesn't open) is what the type-router fixes.

## (1) TYPE-ROUTER — a DECLARED type→renderer map (regression-proof)
Root cause of the regression (PO): mailto handling routed ALL WebItems to the launcher, killing http/https preview. Fix = a single **declared map**, not an if/else cascade where a new scheme silently captures others:
```
WEBITEM_KIND: url-scheme / content-type → kind
  previewable: http, https, (pdf by content-type)      → renderer = PreviewPane (iframe / proxy)
  launcher:    mailto:, message:, tel:, calendar:, sms: → renderer = LaunchAction (OS handoff, no pane)
  default:     unknown scheme → launcher (safe: never auto-iframe an unknown scheme)
```
- One `kindOf(webItem)` resolves scheme+contentType → kind; the renderer is chosen off the map. Adding a launcher scheme (mailto) CANNOT affect the previewable branch — they're independent map entries, not fallthrough. This is the correct-by-construction fix for the regression class.
- A test asserts the map: each scheme → its expected kind (mailto→launcher AND http→previewable in the SAME test, so a future "route all to launcher" edit fails CI).

## (2) CORS PROXY + ★ SSRF GUARD (HARD prod requirement — NEW risk beyond T26.6)
Previewable http/https iframes the URL directly; on `X-Frame-Options`/CSP/CORS block → fall back to a **server-side proxy** (server fetches, sanitizes, returns; preview renders the proxied content). The proxy fetches a **user-provided URL** → an SSRF vector. **HARD requirements (all must hold; prod):**
1. **Scheme allowlist:** only `http`/`https`. Reject `file:`, `gopher:`, `ftp:`, `data:`, `dict:`, everything else.
2. **IP-range block (on the RESOLVED IP, not the hostname):** deny loopback `127.0.0.0/8` `::1`, private `10/8` `172.16/12` `192.168/16`, link-local `169.254/16` `fe80::/10`, unique-local `fc00::/7`, `0.0.0.0/8`, and cloud-metadata `169.254.169.254` + `metadata.google.internal` + `fd00:ec2::254`.
3. **DNS-rebinding defense:** resolve the hostname ONCE, check the resolved IP against the blocklist, then connect to THAT pinned IP (don't let a 2nd resolution swap in an internal IP between check and fetch). Re-check on EVERY redirect hop (a 302 → `http://169.254.169.254` must be blocked).
4. **Size-cap + timeout:** cap response bytes (e.g. a few MB), hard timeout, cap redirect count.
5. **Sanitize + NEVER execute** (reuse the federation/T26.6 discipline): strip `<script>`, inline event handlers, `javascript:`/`data:` URIs; serve with a restrictive CSP; never eval; the proxied content renders as inert.
6. **Content-type allowlist:** `text/html`, `application/pdf`, `image/*` only; reject others (no arbitrary binary).
7. **Rate-limit + audit-log** every proxied fetch (like the Nominatim worker) — abuse + forensics.
Design the proxy as its own Class (`ProxyFetch`/`SafeUrlFetch`) with a `guardUrl(url)` that returns allow/deny+reason BEFORE any socket opens — the guard is a pure, unit-testable predicate (adversarial tests: metadata IP, rebinding, redirect-to-internal, file://).

## (3) LAYOUT (preserve R25.x RbPanZoom)
- **Previewable:** action-row (below the drag-handle) → preview-pane → details-below. Reset-zoom is an **OVERLAY inside the pane** (a floating control), NOT a layout row — so it doesn't disturb `RbPanZoom` pan/zoom state (R25.x). Buttons-above-name invariant (R19.78/BUG3) preserved.
- **Launcher:** no preview-pane; action-row = the launch button (Open in mail/phone/…) + details. No iframe, no proxy.
