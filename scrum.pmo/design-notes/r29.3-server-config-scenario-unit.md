# R29.3 — First-class Server Config Scenario Unit (design, BACKLOG)

**Author:** robbin-architect · 2026-07-02. Plan now, build when scheduled. req 781fa6ac (S29), UC `21b0dc9a` server.configFromScenarioUnit, 7 ACs, crossRef R26.1 (federation). Replaces `.env` for server identity/config with a first-class `ior:class:Server` scenario unit.

## The NEW unit type: `ior:class:Server`
A server's identity + config becomes a scenario unit (versioned, traceable, per-host), not scattered `.env` keys. Model shape:
```
ior:class:Server
model: {
  uuid, name,               // logical name, e.g. "rawbin-prod" / "rawbin-test"
  mode:      'prod'|'test', // replaces NODE_ENV (the env label becomes a typed field)
  domain:    string,        // BASE_DOMAIN — base app domain (rawbin.example)
  hostname:  string,        // canonical FQDN of THIS host — inter-server federation id (R26.1)
  leDomain:  string,        // LE_DOMAIN — the cert's domain (may differ from app domain)
  leCertName:string,        // Let's-Encrypt cert name/ref for THIS domain (per-domain cert)
  osshConfigName: string,   // ossh identity config name (SSH/host identity)
  // extensible: ports/logLevel MAY migrate later; start with identity/domain/cert (the AC scope)
}
ownerIor: <the S29 sprint or an env-root>
```
**Two units, one per host:** `rawbin-prod` (remoteShells 0.2, prod domain+cert) + `rawbin-test` (0.3, test domain+cert). The running server resolves ITS unit by `hostname` (or a pinned `SERVER_UNIT` uuid) — AC-4 (per-host verifiable 0.2+0.3).

**New-type registration (don't forget — new unit type needs plumbing):** register `ior:class:Server` in `templates.ts` (a ServerTemplate, like ClassTemplate) + the trace/tagMap so `/api/trace` renders it + `resolveIor` resolves it. Without this the unit is inert. (Learning: a new scenario type needs a template + tagMap entry, else it doesn't render/resolve.)

## Class + Methods (Class = `ServerConfig`, the resolver; NOT the ior:class:Server data unit)
- **`ServerConfig.fromScenarioUnit`** — resolve THIS host's Server unit (by hostname / pinned uuid), expose domain/mode/hostname/leDomain in place of `envVars['BASE_DOMAIN']`/`['LE_DOMAIN']`/`NODE_ENV` (server.ts:59-84). AC-1 (Server unit) + AC-2 (reads-unit-not-.env, migrate the 3 keys) + AC-7 (migrate + back-compat: fall back to `.env`/`process.env` if no Server unit, so nothing breaks pre-migration).
- **`ServerConfig.selectLECert`** — auto-select the LE cert for the current share-link domain: prod domain → prod cert, test → test (drive off `leCertName`/`leDomain` in the resolved unit). AC-3 (auto-select) + AC-5 (share-links carry domain+cert — the share-link builder reads the resolved unit's domain+cert).
- **hostname → inter-server comms** — the `hostname` field is the federation identity (R26.1 IOR `@originHost`); a peer server resolves another's Server unit by hostname. AC-6 (hostname enables inter-server comms; crossRef R26.1).
- Note: `mode` replacing NODE_ENV pairs with **R29.1's isTTY** — mode is for cert/domain selection (a config fact), NOT for the TUI gate (that stays `process.stdout.isTTY`, a runtime fact). Keep the two orthogonal: mode=which-cert, isTTY=is-there-a-terminal.

## Migration + back-compat (AC-2, AC-7)
- One-shot migrate: read current `.env` (BASE_DOMAIN/LE_DOMAIN/NODE_ENV) on each host → mint that host's Server unit. Idempotent.
- Back-compat: `ServerConfig.fromScenarioUnit` falls back to `.env`/`process.env` when no Server unit is resolvable → zero-downtime cutover; `.env` can be retired per-host once its Server unit is verified.

## Chain (design-ahead, wire now / build later)
UC `server.configFromScenarioUnit` → Class **ServerConfig** (`src/ts/server/server-config.ts`, a NEW focused module — do NOT add to the server.ts monolith; keeps Axis-3 clean) → Methods `fromScenarioUnit` + `selectLECert` → Impls (design-ahead) → Test (per-host 0.2/0.3 resolve + cert-select). crossRef R26.1. The `ior:class:Server` unit type is the DATA; ServerConfig is the CODE that reads it.
