# R30.6.8 — IntelliJ-grade 3-way merge: node-diff3 (base-aware logic) + Monaco 3-pane (retire in-house LCS)

**Author:** robbin-architect 2026-07-13 (DESIGN-ONLY; req = sole minter, S30 backlog, TRON-authorized). Quality bar: **IntelliJ 3-way merge** — LEFT=local | CENTER=result editor (starts as auto-merged, fully-functional w/ autocomplete) | RIGHT=remote; gutter accept-left/right + reject-X per change; "Apply All Non-Conflicting"; sync-scroll.

## The key insight (Tron): IntelliJ is BASE-AWARE → that's diff3, not a 2-view
IntelliJ uses the common-ancestor **BASE** to separate **non-conflicting** changes (one side touched a region → auto-apply) from **true conflicts** (both sides touched the same region → user resolves). That separation IS the **diff3 algorithm** — the real magic. Our in-house LCS has NONE of it; **CM5 MergeView also is NOT base-aware** (it does its own 2-way diffing, no auto-merge/conflict classification). So the spike splits into two layers:

### Layer 1 — merge LOGIC (base-aware): node-diff3 — REQUIRED
`diff3Merge(local, base, remote)` → an array of **ok chunks** (auto-merged: unchanged or one-side-only) + **conflict chunks** (both sides changed the same region, with each side's text). This is exactly IntelliJ's model and gives "Apply All Non-Conflicting" for free (the ok chunks are already merged). Tiny (~a few kB; add dep or vendor ~200 LOC). **Replaces in-house LCS entirely.**

### Layer 2 — 3-pane UI: weighed
| UI option | IntelliJ fidelity | Fit | Verdict |
|---|---|---|---|
| **CM5 MergeView** (turnkey 3-pane + copy-across + sync-scroll) | ✗ **NOT base-aware** — its own 2-way diffing fights diff3; center = CM5 (no Monaco autocomplete); + 2nd editor engine | lighter code, but wrong model | Fallback only |
| **Monaco 3-pane + node-diff3** (local\|result\|remote as 3 Monaco editors; center=result w/ Monaco autocomplete; custom gutter accept/reject driven by diff3 conflicts; sync-scroll across 3) | ✅ **matches IntelliJ** — base-aware, autocomplete center, per-conflict gutter, apply-all-non-conflicting | reuses already-loaded Monaco (no 2nd engine); more custom orchestration | **RECOMMEND** |

### Recommendation: node-diff3 + Monaco 3-pane (the fuller IntelliJ match)
- **Base-aware** (diff3) = the non-negotiable for IntelliJ parity; CM5 can't do it.
- **Center = Monaco result editor** (autocomplete, "fully-functional" like IntelliJ) — reuses our loaded Monaco, no CodeMirror engine.
- **Per-conflict gutter** accept-left / accept-right / reject-X + **Apply-All-Non-Conflicting** (diff3 ok-chunks pre-applied) — our take-over UX, now conflict-aware.
- **BASE input** = git **merge-base** via new `GitApi.mergeBase` (`git merge-base refA refB`, read-only, same execFile/allowlist).
- **Cost/honesty:** more custom orchestration than CM5 (3-editor sync-scroll, custom gutter) — but that orchestration is exactly where IntelliJ quality lives, and it stays Monaco-native. CM5 MergeView remains the lighter non-base-aware fallback if the orchestration is deemed too costly.

## Re-architecture (Class RbDiffEditor 18165081 REUSE)
- **NEW `computeMerge`** — `diff3Merge(local, base, remote)` → ok+conflict chunks (base-aware). **Replaces** `computeDiff` LCS. Pure, DOM-free, unit-testable.
- **NEW `mountMergeView`** — 3 Monaco editors (local RO | result RW | remote RO) via shared `monacoLoader`.
- **NEW `renderConflicts`** — gutter markers per conflict chunk (accept-left/right, reject-X) + "Apply All Non-Conflicting". **Replaces** `renderHunks`.
- **NEW `applyResolution`** — write a chosen side's chunk into the result editor. (Re-scopes `takeHunk` → conflict-aware.)
- **NEW `syncScroll3`** — align scroll across the 3 Monaco editors (IntelliJ sync-scroll).
- **NEW `GitApi.mergeBase`** — `git merge-base refA refB` → base ref for diff3.
- **NEW `monacoLoader`** (shared util, also refactors rb-code-editor).
- **RE-SCOPE** `connectedCallback` (mount 3-pane Monaco + gutter), `loadSide` (now local/base/remote), `swapSides` (swap local↔remote).
- **KEEP** `pickRef`/`pickFile`/`save` (save writes result), **GitApi** branches/commits/fileAtRef, **RepoRegistry**/`RbFileTree.setRepo`.

## AC sketch
- Open merge on two refs → base auto-resolved via `git merge-base`; non-conflicting changes pre-applied in the center result; conflicts flagged in the gutter.
- Accept-left / accept-right / reject per conflict writes into the editable Monaco center; "Apply All Non-Conflicting" is a no-op-if-already (diff3 pre-applied) / applies remaining trivial merges; save writes center to `/api/files`.
- 3 Monaco editors sync-scroll + row-align; center has autocomplete; GitApi/RepoRegistry feed local/remote content (incl OOSH repo, file@ref).
- `computeMerge` unit test: `diff3Merge(local, base, remote)` classifies ok vs conflict chunks correctly (pure, DOM-free).
