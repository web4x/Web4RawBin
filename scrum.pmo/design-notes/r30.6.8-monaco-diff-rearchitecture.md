# R30.6.8 — Re-architect the diff/merge editor onto Monaco (retire in-house LCS)

**Author:** robbin-architect 2026-07-13 (DESIGN-ONLY; req mints a NEW req, S30 backlog, TRON-authorized). Tron directive: R30.6 was built from scratch (in-house LCS); an IntelliJ-grade view (sync-scroll, gutter markers, visual merge) is hard from scratch — **leverage Monaco, which is already loaded** (rb-code-editor, `monaco-editor@0.52.2`).

## Measured state
- **Monaco is already loaded** in `rb-code-editor.ts` via the CDN AMD loader (`.../monaco-editor@0.52.2/min/vs/loader.js` → `req(['vs/editor/editor.main'], monaco => …)`); it uses `monaco.editor.create` / `createModel`. `monaco.editor.createDiffEditor(el, opts)` (sync-scroll + change gutter built-in) IS available in that same bundle.
- **rb-diff-editor.ts (in-house)** — the parts Tron wants replaced: `computeDiff` (15843ac9, LCS→hunks) + `renderHunks` (37636aaa, manual gutter + manual scroll). The parts to keep: 3-pane layout, `takeHunk` (6ebfac12, center merge UX), `loadSide`, `swapSides`, `pickRef`, `pickFile`, `save`, GitApi, RepoRegistry.

## Re-architecture
### 0. Shared Monaco loader (prereq)
Monaco is loaded once inside rb-code-editor. **Extract a shared `monacoLoader` module** (a memoized promise resolving the `monaco` namespace) used by BOTH rb-code-editor and rb-diff-editor — so the diff editor reuses the single loaded instance (no double-load, no CDN race).

### 1. 2-way diff → `monaco.editor.createDiffEditor` (replaces LCS + manual scroll)
- Mount one `createDiffEditor` with `{ original: model(left), modified: model(right) }`. Sync-scroll, side-by-side/inline, and the change gutter are **built-in** — deletes our manual gutter + scroll-sync.
- Hunks come from `diffEditor.getLineChanges()` (Monaco's computed changes) — this replaces our `computeDiff` LCS output as the take-over source.

### 2. 3-way merge → compose 2 Monaco diff editors + KEEP center take-over
- Left pane = `createDiffEditor(base ↔ left)`, Right pane = `createDiffEditor(base ↔ right)`, **Center = editable merged Monaco editor** with our per-hunk take-over buttons (◄ take-left / take-right ►) — **our UX, kept**.
- Needs a **base** source (3rd input): typically the git **merge-base** of left & right. Add optional `GitApi.mergeBase(refA, refB)` (`git merge-base` — read-only, same execFile/allowlist pattern) OR let the user pick the base ref. Take-over resolves each changed region into Center from left or right, sourcing regions from each diff editor's `getLineChanges()`.
- Monaco 0.52 AMD bundle has no standalone merge editor — the 2-diff-editor composition is the pragmatic path Tron specified.

### 3. KEEP unchanged (orthogonal)
3-pane layout shell, `takeHunk` UX, `loadSide` (now sets a Monaco model instead of textarea value), `swapSides`, `pickRef`, `pickFile`, `save`, **GitApi** (branches/commits/fileAtRef), **RepoRegistry** (repo targeting, R30.6.7).

1. **3-way base source:** `GitApi.mergeBase` (auto, cleanest for version-merge) vs user-picks-base-ref. Recommend **mergeBase** (Tron's OOSH-version use case = merge two branches against their common ancestor).
2. **Retire vs re-scope computeDiff:** fully retire the LCS Impl (Monaco owns diffing) vs keep a thin `computeDiff`→`getLineChanges` wrapper for the unit-test AC. Recommend **retire** — Monaco's diff is the source of truth; keep the pure-fn test only if an AC still needs it.
