## ★ #4 CRITICAL — accept ≫/≪ + ✕ have ZERO effect (click-routing regression)
**ROOT (confirmed):** `renderInterPaneGutters` `mk()` attaches the delegated click listener **inside `if (!s)` — i.e., only when the strip is first created** (line ~327), on the STRIP element. R30.16's re-render orchestration (line 251-255: `alignPaneRows` viewZones → `renderCenterChangeBlocks` deltaDecorations → `.de-accept-bar` remove → `renderInterPaneGutters` → `renderConnectorRibbons`) orphans/re-creates the strip so the once-attached listener is lost (tester confirmed: direct `acceptChange(0,'left')` mutates CENTER + the button is hit-testable → it's routing, not logic). 
**FIX (PO/tester-endorsed, bulletproof):** delegate from a STABLE parent attached ONCE. Add a single `click` listener on the component ROOT `this` (never recreated) in `mountThreePane` (c4c84142 impl-edit): `this.addEventListener('click', e => { const b = e.target.closest('[data-cid]'); if(!b) return; const id=+b.dataset.cid; if(b.dataset.act==='ignore'){this.dismissed.add(id); render...} else this.acceptChange(id, b.dataset.act) })`. `renderInterPaneGutters` (fd99c520 impl-edit) DROPS its per-strip `addEventListener` — only sets innerHTML. Delegation via `closest([data-cid])` catches every button in any re-created strip. Markers STAY.

## #1 + #3 — both-sided ribbons + ghost ribbon from empty side (same root)
**ROOT:** `renderConnectorRibbons` (line ~388-395) pushes BOTH bands for EVERY conflict unconditionally — `band(Local→Result)` AND `band(Result→Repository)` — regardless of which side actually holds the change. One-sided change (a left-only add → `c.b.length===0`; a right-only → `c.a.length===0`) still draws a band from the EMPTY side = #1 both-sided + #3 ghost (ribbon from a pane with no content).
**FIX (origin from existing a/b — no full v2 needed):** gate each band on its source side having content — draw Local→Result **iff `c.a.length > 0`**, Result→Repository **iff `c.b.length > 0`** (renderConnectorRibbons 5051b2a4 impl-edit). Gate the gutter take-arrows the same way (renderInterPaneGutters fd99c520 impl-edit): show ≫ (take Local) only if `a.length`, ≪ (take Repo) only if `b.length`. (Optional tiny helper `hunkOrigin(c): 'left'|'right'|'both'` for clarity; inline length-check suffices.) This is the v1-adequate one-sided origin; v2 (surface 3-way one-sided *auto-merged* regions) still separate.

## #2 — OFF-BY-ONE row/ribbon Y-map (right line 70 → center 71)
**ROOT (measured, anchors are consistent — so it's the align offset):** `aStart`/`bStart` = 0-indexed diff start in Local/Repo; `span[0]` = 0-indexed center start (rebuildCenter :226); `lineY(ed,line0)=getTopForLineNumber(line0+1)` converts 0→1-indexed uniformly. Those match. The +1 slip is in the ALIGNMENT vs anchor interaction: `alignPaneRows` (:271-273) inserts spacers `afterLineNumber: aStart+a.length` etc. — mixing 0-indexed block-end arithmetic with Monaco's 1-indexed `afterLineNumber`, and pure-add/del blocks (len 0) shift the anchor by one. Net: a source anchor and the center span drift one row for hunks after a length-delta.
**FIX:** pin all three anchors to the 0-indexed FIRST-CHANGED line of the hunk in each pane; make `alignPaneRows` `afterLineNumber` explicitly the 1-indexed last line of the block (`= start0 + len` is correct only for len>0 — handle len===0 as afterLineNumber=start0, spacer BEFORE the gap); document the index base at each call. **MANDATORY test:** for an aligned hunk, assert `lineY(edRemote, c.bStart) === lineY(edCenter, c.span[0])` (and Local) — post-alignment the source row and its center landing MUST share Y (±0). This is the check the gate needs.

## #5 — file-history selector on RIGHT; convention = older/history on LEFT
**ROOT:** the `.de-history <select>` renders only on `s === 'remote'` (line 77); `pickFile(left)` triggers `populateRightHistory()` (:162) → RIGHT is the history-selectable (older) pane, LEFT = working. Conventional diff = OLD on LEFT, NEW on RIGHT.
**FIX:** move the `<select class="de-history">` to the LEFT pane (`s === 'local'`), repoint history population to the LEFT side (populate the left pane's ref list; rename `populateRightHistory`→`populateLeftHistory` OR add it — the ONE possible new/renamed method), and default LEFT to the file's git history; RIGHT = working/current. Ripple to check (expert): the "Local"/"Repository" pane labels + `swapSides` + acceptChange 'left'/'right' semantics stay, but LEFT now shows the historical version — confirm the labels read old(left)/new(right).
