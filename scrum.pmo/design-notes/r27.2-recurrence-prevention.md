# R27.2 Recurrence Prevention — the BY-CONSTRUCTION guard (design)

**Author:** robbin-architect · 2026-07-01. The 2 open R27.2 ACs (AC-canonical) — what makes "55 dups cannot happen again" STRUCTURAL, not hopeful. Design → expert wires. Two layers (prevention + backstop); neither alone suffices.

**Root cause (measured):** there is NO shared "reuse the existing Class node" helper. Class units are minted ad-hoc in several places — `templates.ts:358` (ClassTemplate factory), `migrate-to-scenario.ts:348`, the objectVerb/chain wiring, and per-req mint scripts. Each per-req chain minted a FRESH Class (`crypto.randomUUID()` + new unit) instead of reusing the existing node for that code-class name → 163 units / 108 names / 55 dups.

## Layer 1 — PREVENTION: reuse-existing-by-code-class-name mint-path
Introduce ONE shared helper (in `src/ts/scenario/classes.ts` or a `ClassRegistry.mintOrReuse`):
```ts
// The ONLY sanctioned way to obtain a Class unit's uuid for a code-class.
mintOrReuseClass(codeClassName: string, ownerIor?: string): string {
  const existing = index.list()
    .map(get).filter(u => u.ior === 'ior:class:Class' && u.model.name === codeClassName);
  if (existing.length) return existing[0].model.uuid;   // REUSE — never mint a 2nd
  const uuid = crypto.randomUUID();
  index.put(uuid, { ior:'ior:class:Class', model:{ uuid, name: codeClassName, methods: [] }, ownerIor });
  return uuid;
}
```
- **Every Class-mint call-site routes through this** — the chain-wiring (objectVerb Chain), `migrate-to-scenario`, ClassTemplate, and the architect/planner mint scripts. A UC that needs a Class asks `mintOrReuseClass(name)` and gets the existing node's uuid — so a code-class has EXACTLY ONE Class unit by construction.
- To ADD a method to that class, append to the returned unit's `methods[]` (same as the R27.2 migration's keeper logic). This is the invariant `chain.reuseCanonicalClass` (UC on R27.2).
- Caveat: name collisions across genuinely-different code classes are near-nil (code-class names are unique in the repo); if ever needed, key on `name` + a namespace, not a fresh mint.

## Layer 2 — BACKSTOP: `trace:audit:strict` fails the build on any violation
Prevention can be bypassed (a script that doesn't use the helper, a hand-edited unit). The un-skippable guarantee is CI. Extend `scripts/trace-audit.ts` (already `--strict` → non-zero exit; already in `npm run ci:gates`) with THREE new structural assertions, each counted into `structuralIssues` so `--strict` FAILS the build:
1. **duplicateClasses = 0:** group all `ior:class:Class` units by `model.name`; ANY name with >1 unit is a violation (list them). This is the exact 55-dup detector — a PR that mints a 2nd Class for an existing name fails CI.
2. **danglingRefs = 0:** every `UC.class`/`classes[]`/`method` (and forward refs) resolves to a unit on disk; a ref to a non-existent uuid (or a literal non-uuid string like the `TODO-server-class`) fails. (Runs AFTER R27.4 clears the current 12.)
3. **orphanMethods = 0 (METHOD-SCOPED, not all-types):** every `ior:class:Method` is in some `Class.methods[]`. ⚠ CRITICAL SCOPE: this is NOT the audit's existing "orphans" metric — that counts ALL unit types unreachable from Requirement roots (~1107+: Devices/Files/Rooms/TestCases/TraceLinks/Tasks — legit non-chain data that can NEVER be 0). The gate is the SPECIFIC defect: a Method not owned by any Class. (Runs AFTER R27.4 attaches the current 51.) Same for orphan-Impls (Impl not owned by a Method).
4. **no LYING orphanByDesign marker:** a Method marked `orphanByDesign`/`designStage` ("no source") whose Impl HAS a real `sourceFile` is a LYING marker (code shipped after the marker) → FAIL. The `orphanByDesign` CI exemption (for #3) is **marker-keyed AND truthful**: exempt a Method from orphanMethods=0 ONLY if it carries the explicit marker AND its Impl has NO sourceFile (genuine design-stage). A marker + real source = the lying case → not exempt, must attach (R27.4 clears these 37).
- Result: `ci:gates` (trace:audit:strict + rule-pair:strict + check:sprint-md) goes RED on: duplicate Class units, dangling refs, orphan Methods. "Cannot recur" becomes a build gate, not a convention.

## Sequencing
- Layer 1 (mint-path) prevents NEW dups immediately — ship first so nothing regresses while R27.4 repairs.
- Layer 2's `duplicateClasses=0` can go strict NOW (R27.2 already collapsed to 1-per-name). `danglingRefs=0` + `orphanMethods=0` go strict AFTER R27.4 clears the 12+51 (else they'd false-fail on the debt R27.4 is repairing — same delta-vs-absolute lesson as R27.2 INV2: don't gate absolute-0 until the debt is cleared).
- Defense-in-depth rationale (as with forward-only stripping / the R27.2 plan+post-apply gates): Layer 1 = fast prevention at authoring time; Layer 2 = the un-skippable guarantee. The invariant LIVES in CI.

## Traceability (aligned to SHIPPED code)
Expert shipped: `src/ts/scenario/class-mint.ts:mintOrReuseClass` (marker `61f24d2c`, the choke-point) + `scripts/trace-audit.ts` `duplicateClasses` (in `hardIssues` → `--strict` fails). **Grouping recommendation: SPLIT** (each Method → its real code module — the very invariant we enforce; grouping 2 methods from 2 modules into 1 `ClassDedupGuard` unit would itself violate one-Class-per-code-module):
- UC `chain.reuseCanonicalClass` (`37c52953`, KEEP) → Class **`ClassMint`** (class-mint.ts) → Method `mintOrReuseClass` → Impl (marker `61f24d2c`, SHIPPED).
- UC `audit.enforceOneClassPerName` → **reuse the EXISTING `TraceAudit` Class** (trace-audit.ts, R24.5) → Method `assertNoDuplicateClasses` → Impl (SHIPPED). Reusing TraceAudit rather than minting a 2nd DOGFOODS the reuse-by-name rule.

**Mint-path coverage (answer to "is migrate-to-scenario authoritative"):** the choke-point is `class-mint.ts:mintOrReuseClass`; `migrate-to-scenario` routes through it; `templates.ts` is a shape factory (not a live create); `skill-classes.ts` reads, never mints. The recent 55 dups came from the TEAM MINT SCRIPTS (req/architect/planner ad-hoc node scripts, not in `src/`) — route the shared chain-mint tooling at `mintOrReuseClass`, and the CI `duplicateClasses=0` gate backstops any script path regardless. Pairs with R27.4 (repairs residual debt) — prevention stops the source, R27.4 cleans the pool.
