# R27.2 — Class-Unit Dedup Migration (design)

**Author:** robbin-architect · 2026-07-01. PO-authorized full-scope, from req's audit [class-unit-dedup-audit.md]. req 64965538 (AC-cleanup + AC-canonical). Design → planner mints the GATED migration task → req 3-point verify. Remap shape = R26.5 `rewriteForwardRefs`.

**Scope:** 163 Class units → 108 (55 collapsible duplicates across 23 code classes). Each code class must have exactly ONE Class node; prior chains minted a fresh Class per requirement → the chain fans out through N duplicate nodes (over-count + broken single-source).

## Canonical selection rule (per code class)
**Use FULL uuids, never 8-char prefixes.** The f2f84ce3 "contradiction" was a PREFIX COLLISION — TWO units share `f2f84ce3`: `f2f84ce3-6f8f-4db1-9ab7-dbcfe8d3bc07` (LIVE RbDetailView, 8m, 21 refs) vs `f2f84ce3-bbbc-4bf7-9345-6a9d4dc64fb5` (DEAD, the R27.4 dangling target). All migration keying is on full uuids only.

**canonical = the LIVE unit with the MOST UC-refs (fewest rewrites); the shipped `[impl:uuid]` marker is PRESERVED by a hard MERGE-CONSTRAINT, not by choosing the marker-unit as canonical.** (PO decision, resolving the 2eeda38d-vs-f2f84ce3-6f8f split.) The marker-rule INTENT is honored as a HARD INVARIANT: **on any method-name collision during merge, KEEP the version carrying a shipped marker / on an active chain** — the shipped method rides to the canonical so live chains derive there, regardless of which unit is canonical. Correctness = the constraint; canonical = chosen for efficiency. Selection order per class:
1. On the **explicit protected list** below → canonical = that named unit.
2. Else → the LIVE unit with the most UC-refs (tiebreak: most methods, then lowest FULL uuid).

## Migration algorithm (per code class, deterministic)
For each code class with N>1 units:
1. Pick canonical `C` per the rule above. `remap = Map<dupUuid → C.uuid>` for the N-1 others.
2. **Move methods (dedup by name):** for each non-canonical `D`, for each method IOR in `D.methods[]`:
   - if `C` already has a method with the SAME `model.name` → it's the same logical method → **collapse**: record `methodRemap[D.method → C.method]`, keep C's (prefer the one with an Impl / on an active chain), drop D's duplicate Method unit.
   - else → append to `C.methods[]` and repoint that `Method.ownerIor → C`.
3. **Rewrite refs across ALL 287 UseCase units:** for every UC, if `UC.model.class` or any entry of `UC.model.classes[]` is a `D` → rewrite to `C.uuid`. If a `UC.method` was method-collapsed (step 2) → rewrite `UC.method` to the kept method. (Same pass shape as R26.5 rewriteForwardRefs: `remap.has(x) ? canonical : keep`.)
4. **Delete the emptied duplicate `D` units** (and any dropped duplicate Method units) — only AFTER their methods are moved and all refs rewritten.

## Gate — DRY-RUN + COUNT first (never silently drop / break)
`--dry-run` (default) emits a per-class table + totals; `--apply` only after the gate passes:
- Per class: `{ canonical, dupsRemoved, methodsMoved, nameCollisionsCollapsed, ucClassRefsRewritten, ucMethodRefsRewritten }`.
- Totals: Class units 163→108 (−55); Method units −(collisions); UC.class refs rewritten = M.
- **HARD INVARIANTS (fail = abort, no apply):**
  1. **No method lost:** distinct method-names per code class BEFORE == AFTER on the canonical (a collapse merges same-name, never drops a distinct method).
  2. **No NEW dangling — DELTA gate (revised per req baseline d1dec787b + PO):** count dangling UC refs (`class`/`classes[]`/`method` → non-existent uuid) BEFORE and AFTER; require AFTER ≤ BEFORE = the migration introduces **0 NEW** dangling. Absolute-0 is NOT the gate — the graph ALREADY has **12 pre-existing dangling UC refs + 51 orphan Methods** (measured baseline), pre-existing debt NOT caused by dedup → the dry-run PDCA must use DELTA so it doesn't false-abort on that debt. The 12 dangling + 51 orphans = a SEPARATE cleanup item (flag PO; candidate R27.3). Intersection rule: if any of the 12 dangling point at a **dup Class being collapsed here**, the remap MUST rewrite them to canonical (bonus reduction) — never delete-and-orphan a ref we could remap. (req enumerating the 12 to confirm which my remap fixes.)
  3. **No orphaned UC / Method:** every Method has a Class owner in `C.methods[]`; every UC still derives Req→UC→Class→Method.
  4. **Active chains derive:** explicit post-migration assertion that R26.1 (IORResolver.resolveFederated), R25.7 (Room dedup 4 UCs), R25.4 (RbDetailDrawer 2 UCs), R26.4-5 (Transfer) STILL derive end-to-end. This is the "protect active-chain dups" gate.
  5. **Idempotent:** re-running --apply is a no-op (0 dups remain).
- Emit the count table as evidence (per the per-count audit-gate pattern); req 3-point verifies against it.

## Edge cases
- **Method-name collision on merge** (e.g. two `renderChainPathSection`): collapse to one (keep active-chain/has-Impl), rewrite UC.method refs — handled in step 2. Prevents the canonical ending with duplicate-named methods.
- **Different ownerIor (sprint) per dup:** canonical keeps ITS ownerIor; merged methods keep their own descriptions. Acceptable (Class ownerIor = nav parent, not a chain edge).
- **A dup referenced by a non-UC** (e.g. a Class listed as another unit's field): the rewrite pass scans ALL units, not just UCs, for any `ior:instance:<dup>` in class-position — safety net.
- **contentHash / File units:** N/A (this is Class dedup only).
