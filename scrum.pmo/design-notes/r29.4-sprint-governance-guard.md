# R29.4 — Sprint Governance: no-auto-mint (design, BACKLOG)

**Author:** robbin-architect · 2026-07-02. Plan now, build when scheduled. req 9e49041e (S29), UC `dd203674` sprintGovernance.tronAuthorizedMint, 5 ACs, crossRef R27.5 (f48fbf5d) + R24.5. **TRON RULE (from S30 on): no agent auto-mints a Sprint; only Tron authorizes.** Sibling to R27.5's chain-gate — SAME audit host, delta-scoped enforcement.

## The invariant
A new Sprint unit is a governance act, not an agent convenience. From **Sprint ≥ 30**, a Sprint unit must carry a **Tron-authorization record**; an agent-minted sprint without it is a violation.

## Authorization record shape (on the Sprint unit)
```
ior:class:Sprint
model: {
  ..., 
  tronAuthorization: {
    authorizedBy: 'Tron',
    ref:  string,        // the Tron directive/message ref that authorized it (evidence, like an AC's evidence-prose)
    at:   string,        // ISO timestamp of the authorization (stamped, not agent-generated)
  }
}
```
The record is EVIDENCE (a pointer to Tron's directive), the same shape as AC evidence-prose — auditable, not forgeable-by-convention.

## ★ CRUX (planner): the ref must be VERIFIABLE, not agent-FABRICABLE (else the choke is bypassable)
This is the R27.7 never-trust-foreign-input pattern applied to governance: an agent can pass `--tron-auth-ref fake`, so a string ref alone is only an audit anchor, not fail-closed. **Measured the actual Tron signal:**
- Tron HAS a distinguishable git identity — `Marcel Donges <marcel.donges@ceruleancircle.com>` (1683 commits) vs agents `freemium user <freemiumuser@example.com>` (393). So author-identity is DISTINGUISHABLE.
- BUT **no GPG-signed commits** (all `%G? = N`). So author email is SPOOFABLE — an agent can `git -c user.email=marcel.donges@… commit`. Author-name verification blocks a SILENT/ACCIDENTAL/non-spoofing agent, not a determined LYING one.
- Tron directives arrive via otmux + occasional `scrum.pmo/tron-*.md` files; no `.tron-auth/` marker path exists yet.

**Verifiability tiers (recommend, strongest → weakest):**
1. **FAIL-CLOSED (strongest):** ref = a **GPG-signed** Tron commit; guard verifies the signature (`git verify-commit` / `%G? = G` + trusted key). Unspoofable. Requires Tron to sign. OR a **Tron-only-writable path** (`.tron-auth/<sprint>.json`) the agents' sandbox genuinely cannot write — the guard checks existence+content.
2. **SEMI (author-check):** ref = a Tron-authored commit; guard checks `%ae == marcel.donges@ceruleancircle.com`. Blocks silent/accidental + agents that don't spoof git config. NOT robust against a lying agent that sets user.email. (Current-reality default.)
3. **AUDIT-ONLY (weakest):** ref = an otmux message id / prose anchor; fabricable; relies on #17-no-fabricate (behavioral). Blocks SILENT mint (traceable review), not a lying agent.

**Recommendation:** ship tier-2 (author-check) NOW as the enforceable floor, and RECOMMEND Tron adopt tier-1 (GPG-sign the authorizing commit, OR write a Tron-only `.tron-auth/<sprint>.json`) to make it truly fail-closed. Be HONEST in the AC about which tier is active — "blocks silent mint" (tier-2/3) is a weaker guarantee than "blocks unauthorized mint" (tier-1), and the AC must not overclaim. The DECISION gate (per planner): which signal does Tron commit to emitting? That picks the tier.
