# R40.20 — Keybar First-Key Toggles Native Keyboard (settable-suppression) (design)

**By:** robbin-architect 2026-08-11, per PO. SHAPE CHANGE to R40.3: OS-keyboard suppression must become a SETTABLE STATE owned by the bar, NOT a by-construction one-way block. First keybar key toggles the native keyboard; the bar is RETAINED and usable in BOTH states. Device-only, real iOS 390. Design → req mints → expert builds → Tron device-verifies → I backstop.

## MEASURED current mechanism (R40.3)
- `RbKeyboardBar.suppressSoftKeyboard(el)` (marker `c3a56e56`, rb-keyboard-bar.ts:23) — a ONE-WAY block applied once at mount: `inputmode=none` (primary: keep focus, no OSK) + `readonly` (belt: OS won't type into it) + autocap/correct/spellcheck off. Called from rb-terminal-detail.ts:79 on the xterm textarea.
- Keybar (rb-keyboard-bar) renders data-driven keys (keymap unit `c16abc17`); each key sends its byte sequence to the SAME R31.4 ws PTY via `sendSeq` (rb-terminal-detail.ts:80). Bar is a BOTTOM COMPARTMENT (flex:0, not an overlay).
⇒ Today the OSK is suppressed by construction, permanently. R40.20 makes it a reversible, bar-owned state.

## The shape change — suppression = settable state owned by the bar
### INV-KB1 — SETTABLE STATE, not a by-construction block (the core)
`RbKeyboardBar` OWNS `keyboardSuppressed: boolean` (default **true** — preserves R40.3's shipped behaviour). Replace the one-shot `suppressSoftKeyboard` with a reversible setter `setKeyboardSuppressed(el, on)`:
- `on=true` → `inputmode=none` + `readonly` (current suppression).
- `on=false` → RESTORE typing: remove `readonly`, set `inputmode` to a typing mode, re-`focus()` the textarea so iOS RAISES the OSK.
The bar is the single owner of this state (no external/by-construction block). Same family as the drawer position-only and the deploy override-as-data: a hardcoded block becomes an owned, settable state. `c3a56e56` is the OLD one-way Impl — do NOT re-credit (R30.11); this is a NEW distinct Impl.

### INV-KB2 — FIRST key toggles
The keybar's FIRST control is a toggle (⌨) that flips `keyboardSuppressed` and applies the KB1 transition. Design pref: the BAR PREPENDS a fixed toggle key it owns (always present regardless of the data-driven keymap `c16abc17`), rather than relying on a keymap entry — so the toggle can never be config'd away. Tap → flip → apply attrs + focus.

### INV-KB3 — RETENTION (HARD AC): bar RETAINED above the keyboard, both states
The bar must NEVER be covered/unmounted when the OSK is up. iOS OSK overlays from the bottom and shrinks `window.visualViewport`. The bar PINS above the keyboard via `visualViewport` `resize`/`scroll`: reposition the bar to `visualViewport.height + offsetTop` (translate up by the keyboard inset) so it sits directly above the OSK; when OSK hides, it returns to the real bottom. The bar element is only REPOSITIONED on toggle, NEVER unmounted. Terminal (host, flex:1) stays visible above the bar in both states.

### INV-KB4 — INPUT REACHES PTY in BOTH states (HARD AC)
- suppressed (keybar-only): keybar keys → `sendSeq` → ws PTY (unchanged).
- un-suppressed (native OSK up): native typing → xterm.js textarea → ws PTY (RESTORED by removing `readonly` + `inputmode=none` — xterm's normal input path), AND the keybar keys STILL reach the PTY (bar retained + functional). Bite: in un-suppressed state, a native keystroke AND a keybar key BOTH land in the PTY.

## What is automatable vs device-only (honest gating, same as R40.3)
- AUTOMATABLE (headless, must gate): `keyboardSuppressed` toggles; the attr transition flips (`inputmode`/`readonly` present when true, absent when false); keybar keys reach the PTY in BOTH states; the `visualViewport` listener fires and REPOSITIONS (bar element stays mounted, transform updates); toggle key present + owned by bar.
- DEVICE-ONLY (real iOS 390 — Tron is the authority, like R40.3): the OSK actually appears/hides on toggle, and the bar is VISIBLY above the keyboard (never covered), usable in both states. Headless WebKit has no OSK = vacuous — do NOT claim device truth from it.
- STUB/BITE: force `setKeyboardSuppressed(false)` → assert typing-restored attrs (RED if still readonly/inputmode=none); toggle back → assert re-suppressed; keybar-key-reaches-PTY bite in both states; retention meta (bar node still connected after toggle).
